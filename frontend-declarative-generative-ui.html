声明式生成式 UI

使用 json-render 和 A2UI，从已注册的组件目录组合智能体生成的界面
约 6 分钟 社区翻译 查看英文原文 ↗

概览#

声明式生成式 UI 位于生成式 UI 谱系的中间位置。智能体输出一份结构化规范，前端则用你预先注册的组件目录组合出界面。智能体的输出就是 UI，而不是聊天气泡中的文本回复：表单、卡片、仪表盘等。你定义哪些组件可用（即“目录”），智能体将它们组合成一棵有效的 UI 树。

目录是让这一方案安全的护栏：智能体可以自由排列和组合你的组件，但无法超出你批准的组件集合。这在创造力与可预测性之间取得平衡。长尾场景正位于此处，用像素级完美换取覆盖广度，适合次要交互、内部工具和仪表盘——在这些场景中，展示有用的内容比精确控制更重要。本页介绍基于 json-render 的声明式生成式 UI，这是一个生成式 UI 框架，可定义组件目录、用 AI 生成规范，并在 React、Vue、Svelte 和 Angular 中安全渲染。关于 Google 的 A2UI 规范（通过 CopilotKit 集成），请参见下文A2UI。

何时使用此方案#

将声明式生成式 UI 用于产品的长尾部分：智能体可以组合你未能完全预料的布局，同时始终处于你批准的组件集合之内，例如次要交互、内部工具和仪表盘。当某个界面流量很高或对品牌至关重要、必须精确控制时，应转向受控生成式 UI。当你希望在应用之外创建界面时，应转向开放式生成式 UI。

工作原理#

  1. 定义目录：声明 AI 可以使用的组件及其带类型的 props

  2. 提示 AI：用自然语言描述你想要的 UI

  3. AI 生成规范：一份描述组件树的 JSON 文档

  4. 安全渲染：json-render 的 Renderer 使用你的组件渲染该规范

目录充当护栏：AI 只能使用你定义的组件，且 props 必须符合你的 schema。输出始终可预测且安全。

定义组件目录#

目录描述了 AI 允许使用的每一个组件。每个组件都为其 props 提供一个 Zod schema，以及一段供 AI 阅读以理解何时使用该组件的描述：

typescript 
import { defineCatalog } from "@json-render/core";
import { schema } from "@json-render/react/schema";
import { z } from "zod";

const catalog = defineCatalog(schema, {
  components: {
    Card: {
      description: "A card container with optional title and padding",
      props: z.object({
        title: z.string().optional(),
        padding: z.enum(["sm", "md", "lg"]).optional(),
      }),
    },
    Stack: {
      description: "Layout children vertically or horizontally with consistent spacing",
      props: z.object({
        direction: z.enum(["vertical", "horizontal"]).optional(),
        gap: z.enum(["sm", "md", "lg"]).optional(),
      }),
    },
    TextInput: {
      description: "A text input field with optional label and placeholder",
      props: z.object({
        label: z.string().optional(),
        placeholder: z.string().optional(),
        type: z.enum(["text", "email", "password", "number", "textarea"]).optional(),
      }),
    },
    Button: {
      description: "A clickable button with label and style variants",
      props: z.object({
        label: z.string(),
        variant: z.enum(["primary", "secondary", "ghost", "link"]).optional(),
        fullWidth: z.boolean().optional(),
      }),
    },
  },
  actions: {},
});
提示

保持目录聚焦。只包含该用例所需的组件。更小的目录比“大杂烩”式方案能产生更好的结果。

构建组件注册表#

注册表将目录中的每个组件映射到其实际的渲染实现。使用 defineRegistry 可在目录 props 与组件函数之间获得类型安全的绑定：

React 
import { defineRegistry, Renderer, JSONUIProvider } from "@json-render/react";

const { registry } = defineRegistry(catalog, {
  components: {
    Card: ({ props, children }) => (
      <div className="card">
        {props.title && <h2>{props.title}</h2>}
        {children}
      </div>
    ),
    Stack: ({ props, children }) => (
      <div className={`stack stack-${props.direction ?? "vertical"} gap-${props.gap ?? "md"}`}>
        {children}
      </div>
    ),
    TextInput: ({ props }) => (
      <div>
        {props.label && <label>{props.label}</label>}
        <input type={props.type ?? "text"} placeholder={props.placeholder} />
      </div>
    ),
    Button: ({ props }) => (
      <button className={props.variant ?? "primary"}>
        {props.label}
      </button>
    ),
  },
});
Vue 
<script setup lang="ts">
import { h } from "vue";
import { defineRegistry, Renderer, JSONUIProvider } from "@json-render/vue";

const { registry } = defineRegistry(catalog, {
  components: {
    Card: ({ props, children }) =>
      h("div", { class: "card" }, [
        props.title ? h("h2", null, props.title) : null,
        children,
      ]),
    Stack: ({ props, children }) =>
      h("div", { class: `stack stack-${props.direction ?? "vertical"} gap-${props.gap ?? "md"}` }, children),
    TextInput: ({ props }) =>
      h("div", null, [
        props.label ? h("label", null, props.label) : null,
        h("input", { type: props.type ?? "text", placeholder: props.placeholder }),
      ]),
    Button: ({ props }) =>
      h("button", { class: props.variant ?? "primary" }, props.label),
  },
});
</script>

连接到智能体#

智能体使用结构化输出返回 json-render 规范。用智能体的 assistant ID 设置 useStream，然后从 AI 消息的 tool_calls 中提取该规范：

React 
import { useStream } from "@langchain/react";
import { AIMessage } from "langchain";

function GenerativeUI() {
  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "generative_ui",
  });

  const aiMessage = stream.messages.find(AIMessage.isInstance);
  const rawSpec = aiMessage?.tool_calls?.[0]?.args;

  // ... filter and render (see streaming section below)
}
Vue 
<script setup lang="ts">
import { useStream } from "@langchain/vue";
import { AIMessage } from "langchain";
import { computed } from "vue";

const stream = useStream<typeof myAgent>({
  apiUrl: "http://localhost:2024",
  assistantId: "generative_ui",
});

const aiMessage = computed(() => stream.messages.value.find(AIMessage.isInstance));
const rawSpec = computed(() => aiMessage.value?.tool_calls?.[0]?.args);
</script>
Svelte 
<script lang="ts">
  import { useStream } from "@langchain/svelte";
  import { AIMessage } from "langchain";

  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "generative_ui",
  });

  const aiMessage = $derived(stream.messages.find((m) => AIMessage.isInstance(m)));
  const rawSpec = $derived(aiMessage?.tool_calls?.[0]?.args);
</script>
Angular 
import { Component } from "@angular/core";
import { injectStream } from "@langchain/angular";
import { AIMessage } from "langchain";

@Component({
  selector: "app-generative-ui",
  template: `...`,
})
export class GenerativeUIComponent {
  stream = injectStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "generative_ui",
  });

  get rawSpec() {
    const ai = this.stream.messages().find(AIMessage.isInstance);
    return ai?.tool_calls?.[0]?.args;
  }
}

流式传输并逐步渲染#

在流式传输过程中，规范是逐步构建的。元素逐个到达，最初可能缺少 type 或 props。筛选出完整的元素，并把 loading={true} 传给 Renderer，这会告诉它静默跳过尚未到达的子元素。UI 逐个组件地构建出来：

tsx 
/*
 * Filter the streamed spec to only include elements with valid type/props,
 * enabling progressive rendering as the AI response builds up. Passing
 * loading={true} to the Renderer tells it to skip missing children silently.
 */
const spec = (() => {
  if (!rawSpec?.root || !rawSpec?.elements) return null;
  const rootEl = rawSpec.elements[rawSpec.root];
  if (!rootEl?.type || rootEl?.props == null) return null;

  const safeElements = {};
  for (const [key, el] of Object.entries(rawSpec.elements)) {
    if (el?.type && el?.props != null) {
      safeElements[key] = el;
    }
  }
  return { root: rawSpec.root, elements: safeElements };
})();

return (
  <>
    {spec && (
      <JSONUIProvider registry={registry}>
        <Renderer spec={spec} registry={registry} loading={stream.isLoading} />
      </JSONUIProvider>
    )}
  </>
);
注意

JSONUIProvider 是设置 json-render 内部上下文提供者（状态、可见性、校验、操作）所必需的。Renderer 组件必须渲染在它内部。

规范格式#

AI 智能体生成一份扁平 JSON 规范，其中 root 键指向根元素，elements 映射包含所有组件：

json 
{
  "root": "login-card",
  "elements": {
    "login-card": {
      "type": "Card",
      "props": { "title": "Login" },
      "children": ["login-stack"]
    },
    "login-stack": {
      "type": "Stack",
      "props": { "direction": "vertical", "gap": "md" },
      "children": ["email-input", "password-input", "submit-btn"]
    },
    "email-input": {
      "type": "TextInput",
      "props": { "label": "Email", "placeholder": "Enter your email", "type": "email" },
      "children": []
    },
    "password-input": {
      "type": "TextInput",
      "props": { "label": "Password", "placeholder": "Enter your password", "type": "password" },
      "children": []
    },
    "submit-btn": {
      "type": "Button",
      "props": { "label": "Sign In", "variant": "primary", "fullWidth": true },
      "children": []
    }
  }
}

每个元素通过 ID 引用其子元素，而像 TextInput 和 Button 这样的叶子元素具有空的 children 数组。

A2UI：另一种声明式规范#

以声明方式描述界面的一种方式是 json-render。A2UI 是另一种：Google 的声明式、流式优先的生成式 UI 规范，通过 CopilotKit 集成。与 json-render 一样，它用你注册的组件组合界面，因此智能体始终处于你定义的护栏之内。A2UI 有两种变体：

  • 动态 schema：由第二个模型根据对话生成完整界面，包括 schema、数据和布局，以实现最大的灵活性。

  • 固定 schema：组件树在前端定义，智能体只向其中流式传输数据，从而实现最快、最可预测的渲染。

详情请参见 CopilotKit 文档中关于 A2UI、动态 schema 和 固定 schema 的内容。要将 CopilotKit 接入 LangGraph 部署，请参见 CopilotKit。

最佳实践#

  • 使用描述性的组件说明：AI 依据这些说明理解何时使用每个组件。清晰的描述会带来更好的 UI 生成结果。

  • 渲染前先校验：在传给 Renderer 之前，始终检查元素是否具有有效的 type 和非空 props，因为流式传输会传递部分数据。

  • 为流式传输而设计：在流式传输期间传入 loading={true}，以便 Renderer 能妥善处理尚未到达的子元素。用户会实时看到 UI 逐步构建，而不必等待完整响应。

  • 使用设计令牌设置样式：使用 CSS 自定义属性，使渲染出的组件自动适应浅色和深色主题。

  • 用 JSONUIProvider 包裹：Renderer 必须位于 JSONUIProvider 之内，才能访问 json-render 用于状态、可见性和操作的内部上下文。
