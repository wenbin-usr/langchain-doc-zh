前端结构化输出

使用自定义 UI 组件渲染智能体的结构化响应，而不是纯文本
约 6 分钟 社区翻译 查看英文原文 ↗

结构化输出让智能体返回有类型的、机器可读的数据，而不是纯文本。你得到的不再是单个字符串，而是一个结构化对象，可以映射到任意 UI：卡片、表格、图表、分步拆解或领域专用的渲染器。

什么是结构化输出？#

智能体不再返回自由格式的文本响应，而是通过工具调用返回符合预定义 schema 的结构化对象。这为你带来：

  • 类型安全的数据：把响应解析为已知的 TypeScript 类型

  • 精确的渲染控制：为每个字段使用各自的 UI 呈现方式

  • 一致的格式：无论底层模型是什么，每个响应都遵循相同的结构

智能体通过调用一个“结构化输出”工具来完成这一点，该工具的参数中包含响应数据。工具本身不执行任何逻辑，只是返回有类型数据的载体。

使用场景#

  • 产品对比：功能表、优缺点列表、评分

  • 数据分析：包含指标、拆解和要点的摘要

  • 分步指南：带说明和代码片段的有序步骤

  • 食谱：食材、步骤、时间和营养信息

  • 数学与科学：用 LaTeX 渲染的公式、逐步推导

  • 旅行规划：包含日期、地点和费用估算的行程

定义 schema#

为智能体返回的结构化数据定义一个 TypeScript 类型。该 schema 的形状决定了你如何渲染 UI。

以下是内嵌演示所用的数学解题 schema：

typescript 
interface MathSolution {
  problem: string; // The original math problem
  steps: {
    explanation: string;
    latex: string; // Optional display math for this step
  }[]; // Step-by-step derivation
  finalAnswer: string; // Plain-text final answer
  finalAnswerLatex: string; // LaTeX representation of the final answer
}

你的 schema 可以是任何内容。无论形状如何，这套模式的工作方式都相同。

从消息中提取结构化输出#

结构化输出位于最后一条 AIMessage 的 tool_calls 数组中。找到 AI 消息并访问第一个工具调用的参数即可提取它：

typescript 
import { AIMessage } from "langchain";

function extractStructuredOutput<T>(messages: any[]): T | null {
  const aiMessage = messages.find(AIMessage.isInstance);
  const toolCall = aiMessage?.tool_calls?.[0];
  if (!toolCall) return null;

  return toolCall.args as T;
}
注意

在智能体完成流式传输之前，结构化输出工具调用可能尚未填充 args。在流式传输过程中，args 可能只被部分填充或为 undefined。渲染前务必检查完整性。

设置 useStream#

将 useStream 连接到你的结构化输出智能体，然后读取 stream.messages 并从最新的 AIMessage 工具调用中提取有类型的载荷。在 args 完成后渲染自定义 UI，在 stream.isLoading 为 true 时显示加载状态（工具参数可能会逐步流入），并使用 stream.submit() 发送下一条提示词。

注意

代码示例使用 useStream<typeof myAgent> 实现类型安全的流状态。请参阅 Python 或 JavaScript 后端的类型推断。

React 
import { useStream } from "@langchain/react";
import { AIMessage } from "langchain";

function MathSolutionChat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "structured_output_latex",
  });

  const solution = extractStructuredOutput<MathSolution>(stream.messages);

  return (
    <div>
      {!solution && !stream.isLoading && (
        <PromptInput onSubmit={(text) =>
          stream.submit({ messages: [{ type: "human", content: text }] })
        } />
      )}
      {stream.isLoading && <LoadingIndicator />}
      {solution && <SolutionCard solution={solution} />}
    </div>
  );
}

渲染结构化数据#

得到有类型的对象后，构建一个组件，把每个字段映射到合适的 UI 元素。这就是该模式的核心：把结构化数据转换为专用的界面。

tsx 
function LatexBlock({ latex }: { latex: string }) {
  return <div className="latex-block">{latex}</div>; // Render with KaTeX or MathJax.
}

function SolutionCard({ solution }: { solution: MathSolution }) {
  return (
    <div className="solution-card">
      <h3>{solution.problem}</h3>
      <ol>
        {solution.steps.map((step, i) => (
          <li key={i}>
            <span>{step.explanation}</span>
            {step.latex && <LatexBlock latex={step.latex} />}
          </li>
        ))}
      </ol>
      <strong>{solution.finalAnswer}</strong>
      {solution.finalAnswerLatex && <LatexBlock latex={solution.finalAnswerLatex} />}
    </div>
  );
}

处理部分流式数据#

在流式传输过程中，工具调用的参数可能是不完整的 JSON。请在你的提取逻辑中对此加以防护：

typescript 
function extractStructuredOutput<T>(
  messages: any[],
  requiredFields: string[] = [],
): T | null {
  const aiMessages = messages.filter(AIMessage.isInstance);
  if (aiMessages.length === 0) return null;

  const lastAI = aiMessages[aiMessages.length - 1];
  const toolCall = lastAI.tool_calls?.[0];
  if (!toolCall?.args) return null;

  const args = toolCall.args as Record<string, unknown>;
  const hasRequired = requiredFields.every(
    (field) => args[field] !== undefined
  );

  if (requiredFields.length > 0 && !hasRequired) return null;
  return args as T;
}

使用 requiredFields 参数，等到关键字段填充完成后再渲染：

typescript 
const solution = extractStructuredOutput<MathSolution>(stream.messages, [
  "problem",
  "steps",
  "finalAnswer",
]);

在流式传输过程中渐进渲染#

不必等待完整的结构化输出，可以随着字段到达逐个渲染。这样在智能体仍在生成时，用户就能获得即时反馈：

tsx 
function ProgressiveSolutionCard({ messages }: { messages: any[] }) {
  const partial = extractStructuredOutput<Partial<MathSolution>>(messages);
  if (!partial) return null;

  return (
    <div className="solution-card">
      {partial.problem && <h3>{partial.problem}</h3>}

      {partial.steps && partial.steps.length > 0 && (
        <div className="solution-steps">
          <h4>Steps</h4>
          {partial.steps.map((step, i) => (
            <div key={i} className="step">
              <div className="step-number">Step {i + 1}</div>
              <p>{step.explanation}</p>
              {step.latex && <LatexBlock latex={step.latex} />}
            </div>
          ))}
        </div>
      )}

      {partial.finalAnswer && <strong>{partial.finalAnswer}</strong>}
    </div>
  );
}
提示

当 schema 具有自然的自上而下顺序时，渐进渲染效果很好：先是问题，然后是推导步骤，最后是最终答案。智能体通常按 schema 顺序生成字段，因此 UI 会自然地填充。

最佳实践#

  • 渲染前校验：务必在渲染前检查必需字段是否存在，因为流式传输可能只送达部分数据

  • 使用通用的提取函数：用类型和必需字段参数化你的提取逻辑，使其可跨不同 schema 使用

  • 渐进渲染：字段到达即显示，而不是等待完整对象，让用户获得即时反馈

  • 提供回退表示：如果某个字段支持富文本渲染（LaTeX、Markdown、图表），也要在 schema 中提供一个纯文本等价形式作为回退

  • 尽量保持 schema 扁平：深层嵌套的 schema 更难渐进渲染，在部分流式传输时也更易出错

  • 让 UI 匹配数据：为每种字段类型选择最能表达它的渲染策略（数组用表格、嵌套对象用卡片、状态字段用徽章）
