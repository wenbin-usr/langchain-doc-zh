人在回路

人在回路（HITL）中间件让你可以为智能体的工具调用添加人工监督。当模型提出可能需要审核的操作时——例如写入文件或执行 SQL——该中间件可以暂停执行并等待决策。
约 19 分钟 社区翻译 查看英文原文 ↗

它的做法是根据可配置的策略检查每一次工具调用。如果需要干预，中间件会发出一个中断以停止执行。图状态通过 LangGraph 的持久化层保存，因此执行可以安全地暂停并在之后恢复。

随后由人的决策决定接下来发生什么：可以按原样批准该操作（approve）、在执行前修改（edit）、带反馈拒绝（reject），或者对“ask user”类工具直接给出回复（respond）。

中断决策类型#

中间件定义了四种内置方式，供人对中断做出响应：

决策类型说明示例场景
✅ approve使用智能体提出的原始参数执行该工具。按原样发送邮件草稿
✏️ edit在执行前修改工具参数。在发送邮件前更改收件人
❌ reject完全跳过这次工具调用，并向智能体返回拒绝反馈。拒绝删除文件并说明原因
💬 respond对于“ask user”类工具，跳过执行，直接以合成工具结果的形式返回人的消息。通过直接回复来回答"ask_user"提示

每个工具可用的决策类型取决于你在interrupt_on中配置的策略。

当多个工具调用同时被暂停时，每个操作都需要单独的决策。

在默认的批量模式下，请按操作在中断请求中出现的顺序提供决策。在单调用模式下，每个工具调用都有自己的中断，并且只接受一个决策。

当人拒绝所请求的操作时，使用reject。仅当人代替工具行事时才使用respond，例如回答ask_user提示。不要用respond来拒绝有副作用的工具，因为其消息会被视为成功的工具结果。

提示

在编辑工具参数时，应保守地做改动。对原始参数的重大修改可能导致模型重新评估其方案，并可能多次执行该工具或采取意料之外的操作。

配置中断#

要使用 HITL，在创建智能体时将中间件添加到智能体的middleware列表中。

你通过一个映射来配置它，该映射把工具操作映射到每个操作允许的决策类型。当工具调用与映射中的某个操作匹配时，中间件会中断执行。

本示例使用默认的批量模式。如需每次工具调用暂停一次，请参阅设置中断模式。

python 
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver


agent = create_agent(
    model="gpt-5.5",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": True,  # All decisions (approve, edit, reject, respond) allowed
                "execute_sql": {"allowed_decisions": ["approve", "reject"]},  # No editing allowed
                "read_data": False, # Safe operation, no approval needed
            },
            # Prefix for interrupt messages - combined with tool name and args to form the full message
            # e.g., "Tool execution pending approval: execute_sql with query='DELETE FROM...'"
            # Individual tools can override this by specifying a "description" in their interrupt config
            description_prefix="Tool execution pending approval",
        ),
    ],
    # Human-in-the-loop requires checkpointing to handle interrupts.
    # In production, use a persistent checkpointer like AsyncPostgresSaver or MongoDBSaver.
    checkpointer=InMemorySaver(),
)
注意

你必须配置检查点保存器，以便在多次中断之间持久化图状态。生产环境中，请使用持久化检查点保存器，例如AsyncPostgresSaver或MongoDBSaver。测试或原型开发时，可使用InMemorySaver。

调用智能体时，传入config，并在其中包含线程 ID，以将执行与某个对话线程关联。详情请参阅LangGraph 中断文档。

配置选项

interrupt_on dict 必填

工具名称到审批配置的映射。值可以是True（使用默认配置中断）、False（自动批准）或InterruptOnConfig对象。

description_prefix string（默认值：Tool execution requires approval）

操作请求描述的前缀

interrupt_mode string（默认值：batched）

智能体如何暂停以等待审核。"batched" 每轮模型调用引发一个中断，通过有序列表作答。"per_call" 每个受拦截的调用引发一个中断，通过中断 ID 作答。"per_call" 需要langchain>=1.4.6。请参阅设置中断模式。

edit_notice string | None

当审核者用edit决策替换某次调用时，在该调用的结果之前添加的文本，让模型知道该调用已被更改。默认值为一条说明人工审核者替换了该调用的提示。传入None则不添加任何内容。

InterruptOnConfig 选项：

allowed_decisions list[string]

允许的决策列表：'approve'、'edit'、'reject'或'respond'

description string | callable

用于自定义描述的静态字符串或可调用函数

when callable

可选谓词，接收ToolCallRequest，返回True表示中断或返回False表示自动批准。可用它根据调用的参数控制是否触发中断。需要langchain>=1.3.3。

条件中断#

默认情况下，interrupt_on 中列出的每次工具调用都会暂停等待审核。若只想让部分调用暂停，可添加when谓词到工具的InterruptOnConfig中。该谓词接收ToolCallRequest，返回True表示中断或返回False表示自动批准，因此你可以根据工具的参数进行控制。

注意

条件中断需要langchain>=1.3.3。

python 
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware, ToolCallRequest
from langgraph.checkpoint.memory import InMemorySaver


def writes_outside_workspace(request: ToolCallRequest) -> bool:
    """Pause writes to paths outside the workspace directory."""
    path = request.tool_call["args"].get("path", "")
    return not path.startswith("/workspace/")


def is_write_query(request: ToolCallRequest) -> bool:
    """Pause SQL that isn't a read-only SELECT."""
    query = request.tool_call["args"].get("query", "")
    return not query.lstrip().upper().startswith("SELECT")


agent = create_agent(
    model="gpt-5.5",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                    "when": writes_outside_workspace,
                },
                "execute_sql": {
                    "allowed_decisions": ["approve", "reject"],
                    "when": is_write_query,
                },
            },
        ),
    ],
    checkpointer=InMemorySaver(),
)

当when谓词返回False时，该调用会直接执行，不会中断。当它返回True，或省略when时，调用照常暂停。求值为False的调用从不会暂停，因此审核者只会看到需要决策的操作。

智能体恢复执行时该谓词会再次运行，因此对同一次调用它必须返回相同结果。如果它在恢复时返回False，工具会直接运行，审核者的答复会被忽略，即使是reject。在批量模式下，如果只有部分调用的结果发生变化，中间件会引发ValueError。

设置中断模式#

中间件以两种模式之一暂停，通过interrupt_mode设置：

  • "per_call"：每个需要审核的工具调用在开始时都会引发自己的中断。每个中断都携带其可接受答案的response_schema。你通过中断 ID 为键，用一个决策来作答。

  • "batched"（默认）：每轮模型调用引发一个中断，列出所有需要审核的调用。你用顺序相同的决策列表作答。

新的智能体应使用单调用模式。LangChain 计划在下一个主版本中将其设为默认。关于并排对比以及单调用模式所解决的问题，请参阅人在回路概览。

每次工具调用暂停一次#

注意

单调用中断需要langchain>=1.4.6。

设置interrupt_mode="per_call"以分别审核每次工具调用。这个智能体对write_file和execute_sql进行拦截审核，并允许read_data无需审核直接运行：

from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver


@tool
def write_file(path: str, content: str) -> str:
    """Write content to a file."""
    return f"Wrote {len(content)} characters to {path}"


@tool
def execute_sql(query: str) -> str:
    """Run a SQL query."""
    return "Deleted 42 rows"


@tool
def read_data(table: str) -> str:
    """Read rows from a table."""
    return f"3 rows from {table}"


agent = create_agent(
    model="google_genai:gemini-3.6-flash",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": True,
                "execute_sql": {"allowed_decisions": ["approve", "reject"]},
                "read_data": False,
            },
            interrupt_mode="per_call",
        ),
    ],
    checkpointer=InMemorySaver(),
)

读取中断#

当模型在一轮中调用全部三个工具时，read_data会立即运行。两个受拦截的调用各自引发一个中断：

python 
config = {"configurable": {"thread_id": "1"}}
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Archive old orders, then delete them."}]},
    config=config,
    version="v2",
)

# One interrupt per gated tool call, in no fixed order
for interrupt in result.interrupts:
    print(interrupt.value)
# > {'type': 'tool_approval', 'tool_call_id': 'call_write', 'name': 'write_file', 'args': {'path': 'orders_archive.csv', 'content': 'id,total\n1,20\n'}, 'description': "Tool execution requires approval\n\nTool: write_file\nArgs: {'path': 'orders_archive.csv', 'content': 'id,total\\n1,20\\n'}"}
# > {'type': 'tool_approval', 'tool_call_id': 'call_sql', 'name': 'execute_sql', 'args': {'query': "DELETE FROM orders WHERE created_at < '2025-01-01'"}, 'description': 'Tool execution requires approval\n\nTool: execute_sql\nArgs: {\'query\': "DELETE FROM orders WHERE created_at < \'2025-01-01\'"}'}

每个中断值都有type: "tool_approval"，因此客户端可以将其与其他中断区分开。tool_call_id、name和args字段标识正在审核的调用。

读取响应模式#

每个中断还携带一个 response_schema：一个 JSON schema，其中为工具允许的每个决策提供一个分支，并按决策的 type 进行匹配。execute_sql schema 有 approve 和 reject 分支。write_file schema 则包含全部四个。对于只允许一个决策的工具，response_schema 就是该决策的 schema 本身，不含 oneOf。

每个标签页展示一个 write_file 分支、一个与之匹配的答案，以及模型收到的 ToolMessage。为便于阅读，下面的分支就地展开 $ref 定义，并省略 title 和 description 字段。

按建议原样运行该调用。

Schema branch 
{"properties": {"type": {"const": "approve", "type": "string"}}, "required": ["type"], "type": "object"}
Answer 
{"type": "approve"}
Model receives 
Wrote 14 characters to orders_archive.csv

            "path": {"type": "string"},

模型会在收到一条说明（审核者替换了该调用）之后收到工具的结果。在中间件上设置 edit_notice 可以更改该说明，或传入 None 将其移除。

Do not re-issue your original call. Executed instead: write_file with arguments {"path": "archive/orders_2024.csv", "content": "id,total\n1,20\n"}.

跳过该调用。message 是可选的，用于告知模型原因。

按 ID 恢复每个调用#

为每个中断提供一个决策作为回答，以中断 ID 为键：

python 
from langgraph.types import Command

decisions = {}
for interrupt in result.interrupts:
    if interrupt.value["name"] == "execute_sql":
        decisions[interrupt.id] = {
            "type": "reject",
            "message": "Archive the rows before deleting them.",
        }
    else:
        decisions[interrupt.id] = {"type": "approve"}

result = agent.invoke(Command(resume=decisions), config=config, version="v2")

你也可以逐个回答中断。未回答的中断会保持待处理状态，其工具会在收到回答后运行。

警告

如果一起发送的多个回答中有一个无效，其他回答对应的工具仍可能运行，而它们的中断仍显示为待处理。再次回答这些中断会导致那些工具运行两次。在一起发送之前，请对照 response_schema 检查各个回答，或者逐个发送。

修正无效的回答#

LangGraph 在保存回答之前，会对照中断的 response_schema 检查每个回答。无效的回答会抛出 ValidationError，且不会保存任何内容，因此你可以向同一个中断 ID 发送修正后的回答。这里，该编辑遗漏了 content：

python 
from pydantic import ValidationError

write_file_interrupt = next(
    interrupt for interrupt in result.interrupts if interrupt.value["name"] == "write_file"
)
edit = {
    "type": "edit",
    "edited_action": {"name": "write_file", "args": {"path": "archive/orders_2024.csv"}},
}

try:
    agent.invoke(Command(resume={write_file_interrupt.id: edit}), config=config, version="v2")
except ValidationError as error:
    for problem in error.errors():
        print(".".join(str(part) for part in problem["loc"]), problem["msg"])
# > edit.edited_action.args.content Field required

# Nothing was saved, so answer the same interrupt again
edit["edited_action"]["args"]["content"] = "id,total\n1,20\n"
result = agent.invoke(
    Command(resume={write_file_interrupt.id: edit}), config=config, version="v2"
)

每个错误都会指出校验失败的字段，因此你可以将其展示给审核者。对于参数是原始 JSON schema 而非 Pydantic 模型的工具，response_schema 会显示参数，但 LangGraph 不会对照这些参数检查编辑内容。

为逐调用审核排列中间件顺序#

在逐调用模式下，审核在工具调用开始时进行，位于工具调用中间件链内：

  • 请将 HumanInTheLoopMiddleware 列在工具重试或错误处理中间件（例如 ToolRetryMiddleware 和 ToolErrorMiddleware）之前，以便它包裹这些中间件。否则，被重试的调用会再次询问审核者，无效的回答会被重试或作为工具错误返回给模型。

  • 当智能体恢复时，列在 HumanInTheLoopMiddleware 之前的中间件会重新运行到暂停点，因此它在调用其处理器之前不得产生副作用。工具只在收到回答后运行。

  • when 谓词 会在每次调用开始时运行，因此它接收到的 ToolCallRequest 会包含该工具。

响应中断#

当你调用智能体时，它会一直运行，直到完成或抛出中断。当某个工具调用匹配你在 interrupt_on 中配置的策略时，就会触发中断。使用 version="v2" 时，结果是一个 GraphOutput，其 interrupts 属性包含需要审核的操作。随后你可以将这些操作呈现给审核者，并在提供决策后恢复执行。

本节中的示例以及下文介绍的决策类型均使用默认的批处理模式。关于逐调用模式，请参阅 Pause once per tool call。

python 
from langgraph.types import Command

# Human-in-the-loop leverages LangGraph's persistence layer.
# You must provide a thread ID to associate the execution with a conversation thread,
# so the conversation can be paused and resumed (as is needed for human review).
config = {"configurable": {"thread_id": "some_id"}}
# Run the graph until the interrupt is hit.
result = agent.invoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "Delete old records from the database",
            }
        ]
    },
    config=config,
    version="v2",
)

# result is a GraphOutput with .value and .interrupts
print(result.interrupts)
# > (
# >    Interrupt(
# >       value={
# >          'action_requests': [
# >             {
# >                'name': 'execute_sql',
# >                'args': {'query': 'DELETE FROM records WHERE created_at < NOW() - INTERVAL \'30 days\';'},
# >                'description': 'Tool execution pending approval\n\nTool: execute_sql\nArgs: {...}'
# >             }
# >          ],
# >          'review_configs': [
# >             {
# >                'action_name': 'execute_sql',

# >    ),
# > )


# Resume with approval decision
agent.invoke(
    Command(
        resume={"decisions": [{"type": "approve"}]}  # or "reject" [!code highlight]
    ),
    config=config, # Same thread ID to resume the paused conversation

提示

编辑 工具参数时，请保守地做出修改。对原始参数的重大修改可能导致模型重新评估其方案，并可能多次执行工具或采取意外操作。

使用 reject 拒绝工具调用，并提供反馈而非执行。该工具不会被执行。

python 
agent.invoke(
    Command(
        # Decisions are provided as a list, one per action under review.
        # The order of decisions must match the order of actions
        # in the interrupt request.
        resume={
            "decisions": [
                {
                    "type": "reject",
                    # Optional: explain why the action was rejected
                    # and whether the agent should retry a different approach.
                    "message": "User rejected this action. Do not retry this tool call.",
                }
            ]
        }
    ),
    config=config,  # Same thread ID to resume the paused conversation
    version="v2",
)

message 会作为反馈添加到对话中，帮助智能体理解该操作为何被拒绝，以及它应该改做什么。省略 message 时，中间件会使用默认的拒绝消息，告知模型该工具未被执行，且除非用户要求，否则不要重试同一个工具调用。对于有副作用的工具，请提供特定领域的消息，明确说明智能体应当放弃该操作、追问后续问题，还是尝试更安全的替代方案。

对于“询问用户”类工具——其真正的实现就是人类的回答——请使用 respond。message 的内容会直接作为工具结果返回，工具本身不会被执行。

python 
agent.invoke(
    Command(
        # Decisions are provided as a list, one per action under review.
        # The order of decisions must match the order of actions
        # in the interrupt request.
        resume={
            "decisions": [
                {
                    "type": "respond",
                    # The human's reply, returned directly as the tool result
                    "message": "Blue.",
                }
            ]
        }
    ),
    config=config,  # Same thread ID to resume the paused conversation
    version="v2",
)

message 会作为成功的 ToolMessage 返回给智能体。当工具本身就是有意作为人类输入的占位符时，请使用 respond，例如一个用于请求澄清的 ask_user 工具。不要使用 respond 来拒绝某项提议的操作，因为它会告诉模型该工具已成功完成。

人在回路中的流式传输#

你可以使用 stream_events() 在智能体运行并处理中断的同时流式传输实时更新。使用 stream.messages 流式传输 LLM token，使用 stream.values 检查智能体状态快照中的中断。

python 
from langgraph.types import Command

config = {"configurable": {"thread_id": "some_id"}}

# Stream agent progress and LLM tokens until interrupt
stream = agent.stream_events(
    {"messages": [{"role": "user", "content": "Delete old records from the database"}]},
    config=config,
    version="v3",
)
for message in stream.messages:
    for token in message.text:
        print(token, end="", flush=True)

# Check whether the run paused for human input
if stream.interrupted:
    print(f"\n\nInterrupt: {stream.interrupts}")

# Resume with streaming after human decision
stream = agent.stream_events(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config,
    version="v3",
)
for message in stream.messages:
    for token in message.text:
        print(token, end="", flush=True)

在 逐调用模式 下，stream.interrupts 为每个受控工具调用保存一个中断。使用以中断 ID 为键的 dict 恢复：

python 
decisions = {interrupt.id: {"type": "approve"} for interrupt in stream.interrupts}
stream = agent.stream_events(Command(resume=decisions), config=config, version="v3")
for message in stream.messages:
    for token in message.text:
        print(token, end="", flush=True)

执行生命周期#

该中间件定义了一个 after_model 钩子，它在模型生成响应之后、任何工具调用执行之前运行：

  1. 智能体调用模型生成响应。

  2. 中间件检查响应中是否包含工具调用。

  3. 如果有任何调用需要人类输入，中间件会使用 action_requests 和 review_configs 构建一个 HITLRequest，并调用 interrupt。

  4. 智能体等待人类的决策。

  5. 根据 HITLResponse 决策，中间件执行已批准或已编辑的调用，为被拒绝的调用合成 ToolMessage，对 respond 决策直接将人类回复作为 ToolMessage 返回，并恢复执行。

在 逐调用模式 下，after_model 钩子不执行任何操作。中间件改为在每个受控调用运行时暂停它，每次调用有一个 interrupt，并在该调用的决策到达后运行工具。
