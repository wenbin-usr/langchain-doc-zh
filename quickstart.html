LangChain/开始使用/快速开始

快速开始

在几分钟内构建你的第一个智能体
约 21 分钟 社区翻译 查看英文原文 ↗

本快速入门将向你展示如何在短短几分钟内创建一个功能完备的 AI 智能体。

构建 LangChain 快速入门智能体

按照 LangChain 快速入门，在此工作目录中构建一个基础的 LangChain 智能体。

第 1 步：阅读指南#

检测此项目使用的是 Python 还是 TypeScript/JavaScript。获取并遵循对应的页面；将其作为包名、模型字符串和代码的权威依据：

  • Python：https://docs.langchain.com/oss/python/langchain/quickstart.md

  • TypeScript：https://docs.langchain.com/oss/javascript/langchain/quickstart.md

第 2 步：安装依赖#

使用项目已有的包管理器（uv、pip、npm、pnpm、yarn 或 bun）安装指南中列出的包。如果项目已经固定了版本，优先固定当前稳定版本，而不是使用浮动的 latest 标签。

第 3 步：配置模型凭据#

检查是否已设置受支持的模型提供商 API 密钥（例如 OPENAI_API_KEY、GOOGLE_API_KEY 或 ANTHROPIC_API_KEY）。若均未设置，询问用户使用哪个提供商，然后暂停并等待其创建密钥并在 shell 或 .env 文件中设置。不要凭空编造、硬编码或提交 API 密钥。

第 4 步：实现基础智能体#

按指南创建“构建基础智能体”示例：create_agent、一个简单工具（如 get_weather）、一段简短的提示词，以及一次 invoke 调用。使用用户所选提供商的模型字符串。打印最终消息内容（Python：.content_blocks），以便用户验证运行结果。

第 5 步：可选的 LangSmith 追踪#

询问用户是否需要追踪。若需要，遵循 https://docs.langchain.com/langsmith/create-an-agent 在基于智能体的工作区中注册智能体。让其设置 LANGSMITH_AGENT_ID、LANGSMITH_AGENT_ENVIRONMENT、LANGSMITH_TRACING=true 和 LANGSMITH_API_KEY，然后重新运行。不要编造 LangSmith 密钥。

规则#

  • 将范围限定在本快速入门内。不要添加无关的框架、评估或生产部署。

  • 如指南所示，优先使用 create_agent（来自 langchain.agents / langchain）。

  • 当密钥、提供商选择或项目约定不明确时，应询问而非猜测。

提示

使用 AI 编码助手？

  • 安装 LangChain Docs MCP 服务器，让你的智能体能够访问最新的 LangChain 文档和示例。

    连接 LangChain 文档 MCP 服务器

    将两个 LangChain 文档 MCP 服务器连接至我的编码智能体，使其能够查询最新的 LangChain、LangGraph 和 LangSmith 文档与 API 参考。

    要添加的服务器：

    • docs-langchain: https://docs.langchain.com/mcp

    • reference-langchain: https://reference.langchain.com/mcp

    检测我正在使用哪个智能体或编辑器（Claude Code、Cursor、Codex CLI、Claude Desktop、Deep Agents Code、VS Code、Antigravity 或其他兼容 MCP 的客户端）。使用 https://docs.langchain.com/use-these-docs.md 中对应的配置方式：

    • Claude Code：为每个服务器执行 claude mcp add --transport http（默认为项目范围；仅当我要求全局访问时才使用 --scope user）。

    • Codex CLI：使用每个服务器 URL 执行 codex mcp add。

    • Cursor、Deep Agents Code、VS Code 或 Antigravity：使用该页面上针对我的客户端所示的字段名，将两个条目合并到 MCP 设置 JSON 中。

构建基础智能体#

首先创建一个能够回答问题并调用工具的简单智能体。本示例中的智能体使用所选的语言模型、一个基础的天气函数作为工具，以及一段简单的提示词来引导其行为：

from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    system_prompt="You are a helpful assistant",
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What's the weather in San Francisco?"}]}
)
print(result["messages"][-1].content_blocks)

构建真实场景智能体#

在下面的示例中，你将构建一个能够回答文本文件相关问题的研究智能体。在此过程中，你将了解以下概念：

  1. 详细的系统提示词，以获得更好的智能体行为

  2. 创建工具，与外部数据集成

  3. 模型配置，确保响应一致

  4. 对话记忆，实现类聊天式交互

  5. Deep Agents，提供内置功能

  6. 测试你的智能体

1. 定义系统提示词

系统提示词定义智能体的角色和行为。请保持具体且可执行：

python 
SYSTEM_PROMPT = """You are a literary data assistant.

## Capabilities

- `fetch_text_from_url`: loads document text from a URL into the conversation.
Do not guess line counts or positions—ground them in tool results from the saved file."""

2. 创建工具

工具 让模型能够通过调用你定义的函数与外部系统交互。工具可以依赖 运行时上下文，也可以与 智能体记忆 交互。

本示例使用一个工具从给定的 URL 加载文档：

python 
import urllib.error
import urllib.request

from langchain.tools import tool


@tool
def fetch_text_from_url(url: str) -> str:
    """Fetch the document from a URL.
    """
    req = urllib.request.Request(
        url,
        headers={"User-Agent": "Mozilla/5.0 (compatible; quickstart-research/1.0)"},
    )
    try:
        with urllib.request.urlopen(req, timeout=120) as resp:
            raw = resp.read()
    except urllib.error.URLError as e:
        return f"Fetch failed: {e}"
    text = raw.decode("utf-8", errors="replace")
    return text
提示

工具应有完善的文档：其名称、描述和参数名会成为模型提示词的一部分。LangChain 的 @tool 装饰器 会添加元数据，并通过 ToolRuntime 参数启用运行时注入。在 工具指南 中了解更多。

4. 添加记忆

为智能体添加 记忆，以便在多次交互之间保持状态。这使智能体能够记住之前的对话和上下文。

python 
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()
注意

在生产环境中，应使用可将消息历史保存到数据库的持久化检查点存储。更多详情请参阅 添加和管理记忆。

5. 创建并运行智能体

现在，用上述所有组件组装你的智能体并运行它。

创建智能体有两种不同的框架：LangChain 智能体和 Deep Agents。LangChain 与 Deep Agents 都为你提供对工具、记忆等的细粒度控制。两者的主要区别在于，Deep Agents 已内置一系列常用能力，例如规划、文件系统工具和子智能体。

当你希望以最少配置获得最强能力时，请使用 Deep Agents；当你需要细粒度控制时，请选择 LangChain 智能体。

为了在本步骤中对比两者，请安装 deepagents 包：

uv add deepagents
pip install -U deepagents
警告

本示例会把《了不起的盖茨比》的全文发送给模型，响应可能需要一两分钟。你可以在下一步中查看示例输出。

下面把两者都试一下：

python 
from langchain.agents import create_agent
from deepagents import create_deep_agent

agent = create_agent(
    model=model,
    tools=[fetch_text_from_url],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
)

deep_agent = create_deep_agent(
    model=model,
    tools=[fetch_text_from_url],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
)

content = f"""Project Gutenberg hosts a full plain-text copy of F. Scott Fitzgerald's The Great Gatsby.
URL: https://www.gutenberg.org/files/64317/64317-0.txt

Answer as much as you can:

1) How many lines in the complete Gutenberg file contain the substring `Gatsby` (count lines, not occurrences within a line, each line ends with a line break).
2) The 1-based line number of the first line in the file that contains `Daisy`.
3) A two-sentence neutral synopsis.

Do your best on (1) and (2). If at any point you realize you cannot **verify** an exact answer with
your available tools and reasoning, do not fabricate numbers: use `null` for that field and spell out
the limitation in `how_you_computed_counts`. If you encounter any errors please report what the error was and what the error message was."""

print("Running create_agent...", flush=True)
agent_result = agent.invoke(
    {"messages": [{"role": "user", "content": content}]},
    config={"configurable": {"thread_id": "great-gatsby-lc"}},
)
print("Running create_deep_agent...", flush=True)
deep_agent_result = deep_agent.invoke(
    {"messages": [{"role": "user", "content": content}]},
    config={"configurable": {"thread_id": "great-gatsby-da"}},
)
print("\ncreate_agent:")
print(agent_result["messages"][-1].content_blocks)
print("\ncreate_deep_agent:")
print(deep_agent_result["messages"][-1].content_blocks)

下面的折叠面板把全部内容整合在一个可运行的脚本中：

完整示例代码

python 
import urllib.error
import urllib.request

from langchain.agents import create_agent
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver

SYSTEM_PROMPT = """You are a literary data assistant.

## Capabilities

- `fetch_text_from_url`: loads document text from a URL into the conversation.
Do not guess line counts or positions—ground them in tool results from the saved file."""


@tool
def fetch_text_from_url(url: str) -> str:
    """Fetch the document from a URL.
    """
    req = urllib.request.Request(
        url,
        headers={"User-Agent": "Mozilla/5.0 (compatible; quickstart-research/1.0)"},
    )
    try:
        with urllib.request.urlopen(req, timeout=120) as resp:
            raw = resp.read()
    except urllib.error.URLError as e:
        return f"Fetch failed: {e}"
    text = raw.decode("utf-8", errors="replace")
    return text

追踪智能体调用#

注意

在基于智能体的工作区中，需先创建智能体一次，然后再发送追踪数据。使用智能体寻址来选择其标识符和环境。如果某个集成需要 project_name，请使用所选环境的 tracer_session_name 作为兼容值。

你用 LangChain 构建的大多数有价值的智能体都会多次调用 LLM。随着这些智能体变得愈发复杂，能够检查智能体内部究竟发生了什么就变得很重要。最好的方式是使用LangSmith。

注册LangSmith账号并设置以下环境变量，即可开始记录追踪数据：

bash 
export LANGSMITH_AGENT_ID="<your-agent-id>"
export LANGSMITH_AGENT_ENVIRONMENT="local"
export LANGSMITH_TRACING="true"
export LANGSMITH_API_KEY="..."

设置完成后，再次运行脚本，然后在LangSmith 上查看智能体调用期间发生了什么。

提示

如需进一步了解如何使用 LangSmith 追踪你的智能体，请参阅LangSmith 文档。

我们还建议你设置LangSmith Engine，它可以监控你的追踪数据、检测问题并提出修复建议。
