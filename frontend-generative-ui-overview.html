生成式 UI 概览

了解从受控到声明式再到开放式的生成式 UI 谱系
约 3 分钟 社区翻译 查看英文原文 ↗

生成式 UI 是指智能体的输出以文本之外的形式呈现用户界面的任何模式。智能体不再把一段文字流式传输到聊天气泡中，而是驱动表单、卡片、仪表盘和交互控件。这让你 UI 能以应用的方式传达结果，同时由智能体决定展示什么以及何时展示。

生成式 UI 不是单一技术。它跨越一个谱系，而这个谱系由同一个问题界定：界面由谁编写？在一端，你编写每一个组件，智能体只在其中做选择。在另一端，界面完全在你的应用之外创建。沿谱系推进，就是以可预测性换取表达范围。

从左向右，可预测性和单项能力的工程成本都在下降，而智能体的表达范围在扩大。可访问性和视觉一致性在左侧最容易保证，在右侧最难保证。

受控式#

你编写组件，由智能体选择渲染哪一个以及传入什么数据。这带来最高的可预测性，以及对品牌和可访问性最严格的控制，代价是每暴露一项能力都要编写一个组件。它是生成式 UI 的主力方案，适合高流量、品牌至关重要的界面，这类界面的布局必须精确，例如机票和预订确认。你的组件库就是边界：智能体只能渲染你已交付的内容。受控式生成式 UI 涵盖将组件作为工具、工具调用渲染、状态渲染和推理。

详情请参见 受控式生成式 UI。

声明式#

智能体输出结构化的规范，前端则从你事先注册的组件目录中组合出界面。该目录既是护栏也是边界：智能体可以自由排列和组合你的组件，但不能超出你批准的集合。长尾场景正位于此处。它以像素级的精确度换取广度，适合次要交互、内部工具和仪表盘，在这些场景中展示有用的内容比精确控制更重要。声明式生成式 UI通过 json-render 实现了这一点；Google 的 A2UI 通过 CopilotKit 集成，以动态和固定 schema 两种变体提供相同的形态。

开放式#

智能体掌控画布。界面在你的应用之外创建，例如由 MCP 服务器创建，并在沙箱中渲染。这带来最广的表达范围，并且可以在你这边无需任何前端代码的情况下增加新的界面能力，适合一次性的可视化和定制化回答，这类场景中一个令人惊喜且足够好的结果胜过可预测的结果。它也是最实验性的方式：确定性最低，最难保证可访问性、一致性和安全性，因此 UI 必须隔离。沙箱和你的提示词就是边界。

详情请参见 开放式生成式 UI。

选择方案#

从你需要对界面施加多少约束出发：

如果你需要……选择
为已知的一组输出保证品牌、布局和可访问性受控式
让智能体仅使用已批准的组件组合出新颖布局声明式
呈现第三方编写的界面，而无需自行构建开放式

为整个产品只选一种方案是最常见的错误。真实应用会混合使用多种方案，让每个界面各司其职：高流量、品牌关键的核心使用受控组件，次要交互的长尾使用声明式组合，第三方能力使用开放式嵌入。同一个会话可以跨越全部三种方式。

该谱系同样适用于聊天之外的场景。同样的三种方式也描述了移动端以及 Slack 或电子邮件等界面中的生成式界面，而不只是聊天记录。

探索该谱系#

受控式

你编写组件；智能体挑选渲染哪一个以及传入什么数据。

声明式

智能体输出规范；前端从已注册的目录中组合界面。

开放式

渲染在别处创建的 UI，例如沙箱中的 MCP Apps。
