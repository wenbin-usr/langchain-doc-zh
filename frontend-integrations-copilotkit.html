CopilotKit

结合自定义端点、Python AG-UI 桥接层、结构化生成式 UI 和消息平台渠道，将 CopilotKit 与 LangGraph、Deep Agents 和 React 一起使用
约 19 分钟 社区翻译 查看英文原文 ↗

CopilotKit 提供完整的 React 聊天运行时，当你希望智能体返回 结构化 UI 载荷 而不只是纯文本时，它与 LangGraph 尤其契合。前端与 CopilotKit 运行时 URL 通信，并把助手消息解析为动态 React 组件。

在这种模式中，你的 LangGraph 部署同时提供图 API 和一个 AG-UI FastAPI 桥接层。一个轻量的 Node CopilotKit 运行时位于该桥接层之前，由 React 客户端调用。

在服务端，copilotkit 包提供 CopilotKitMiddleware，使 LangGraph 图、LangChain 智能体或 Deep Agent 能够使用 Agent UI (AG-UI) 线路协议，向聊天 UI 流式传输工具和消息事件，并读写共享的 CopilotKit 状态切片。TypeScript 方案通常把 CopilotKit 运行时挂载在图 API 旁边。Python 方案在部署上挂载 AG-UI FastAPI 桥接层，并在其前面以 Node 运行 CopilotKit 运行时。

当你需要以下能力时，这种方法很有用：

  • 现成的聊天运行时，无需自己接入 stream.messages

  • 自定义服务端端点，可在已部署的图旁边添加特定于提供商的行为

  • 由受限组件注册表渲染的结构化生成式 UI

CopilotKit for LangGraph 还在相同的中间件和客户端之上介绍了 生成式 UI、人在回路（HITL）和 共享状态。

注意

关于 CopilotKit 特有的 API、UI 模式和运行时配置，请参阅 CopilotKit 文档。关于 Deep Agent 的完整演练，请参阅 CopilotKit 文档中的 Deep Agents and CopilotKit。

工作原理#

从高层来看，CopilotKit 位于你的 React 应用与 LangGraph 部署之间。

前端把对话状态发送给 Node CopilotKit 运行时。该运行时调用你 LangGraph 部署上的 AG-UI FastAPI 桥接层，响应中同时返回助手消息和你的组件注册表能够渲染的任何结构化 UI 载荷。

  1. 像往常一样部署图，可以使用 LangSmith，也可以使用 LangGraph 开发服务器。

  2. 用 HTTP 应用扩展部署，在图 API 旁边挂载 AG-UI FastAPI 桥接层。

  3. 运行一个 Node CopilotKit 运行时，让 HttpAgent 指向该桥接层，然后用 CopilotKit 包裹前端并指向运行时 URL。

  4. 注册动态 UI 组件，并在渲染时把助手响应解析为这些组件。

在 Python 方案中，CopilotKit 运行时是一个独立的 Node 进程。LangGraph 部署只托管图 API 和 AG-UI FastAPI 桥接层。参见 添加 CopilotKit 运行时。

Python 服务端提供的能力#

copilotkit 及相关包在 LangGraph 部署与 CopilotKit 客户端之间架起桥梁。

组件作用
CopilotKitMiddleware把 CopilotKit 和 AG-UI 的状态与请求合并进你的智能体，包括前端的 工具调用 和上下文。将其加入 create_agent 或 create_deep_agent 的 middleware 列表。
CopilotKitState（子类）自定义状态：扩展 CopilotKitState，使 CopilotKit 键成为图状态的一部分。
LangGraphAGUIAgent将已编译的图连同名称和描述打包，供运行时使用。
add_langgraph_fastapi_endpoint（来自 ag-ui-langgraph）在你的图所在的同一个 LangGraph 进程中接入 FastAPI AG-UI 桥接层。用 custom http 应用在 langgraph.json 中挂载它。React 客户端仍需要一个独立的 Node CopilotKit 运行时，通过 AG-UI 调用该桥接层。

CopilotKitMiddleware 是同一个中间件，既适用于 create_deep_agent，也适用于来自 create_agent 的图（当你把它加入 middleware 列表时）。对于 create_agent 图（带有 CopilotKitState 和 FastAPI 桥接层），请参照下面的 Python main.py 示例。结构化生成式 UI（例如 useAgentContext 以及客户端传入的 output_schema）需要额外的中间件，把 Copilot 状态映射为 结构化输出 策略，如同一节中可展开的 src/middleware.py 示例所示。

在 langgraph.json 中把 app 挂载到 http 键上，遵循通常的 LangGraph 或 LangSmith 部署 方式：一个进程同时提供图 API 和 AG-UI FastAPI 桥接层。CopilotKit React 客户端与 Node 运行时通信，再由运行时调用该桥接层。

将 CopilotKit 与 Deep Agent 配合使用#

把 CopilotKitMiddleware 加入传给 create_deep_agent 的 middleware 列表。该中间件使 CopilotKit 能够路由前端工具调用，并使聊天状态与图保持一致。你配置的其他 中间件 也应保留在同一列表中。

随后，已编译的图即可接入支持 CopilotKit 或 AG-UI 的进程（例如下面的 FastAPI 模式），或参照 CopilotKit 文档中的 Deep Agents and CopilotKit 指南。如果你在 langgraph.json 的 graphs 下列出导出的智能体，不要在其上传入检查点保存器。下面的 FastAPI 示例 只在 AG-UI 路由所用的副本上附加检查点保存器。

python 
from deepagents import create_deep_agent
from copilotkit import CopilotKitMiddleware


def get_weather(location: str) -> str:
    """Return a simple weather string for a location."""
    return f"The weather in {location} is sunny."


agent = create_deep_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    middleware=[CopilotKitMiddleware()],  # AG-UI, frontend tools, and context
    system_prompt="You are a helpful research assistant.",
)

用自定义端点扩展 LangGraph 部署#

关键思路在于，LangGraph 部署不仅仅提供图服务，它还能加载 HTTP 应用，从而让你在部署本身之外挂载额外路由。

在 langgraph.json 中，把 http.app 指向你的自定义应用入口：

json 
{
  "dependencies": ["."],
  "graphs": {
    "copilotkit_shadify": "./main.py:agent"
  },
  "http": {
    "app": "./main.py:app"
  }
}

在 Python 中，创建一个 FastAPI 应用，并通过 CopilotKit 的 AG-UI 桥接层暴露 LangGraph 智能体：

main.py 
from typing import Any, TypedDict

from ag_ui_langgraph import add_langgraph_fastapi_endpoint
from copilotkit import CopilotKitMiddleware, CopilotKitState, LangGraphAGUIAgent
from fastapi import FastAPI
from langchain.agents import create_agent
from langgraph.checkpoint.memory import MemorySaver

from src.middleware import apply_structured_output_schema, normalize_context


class AgentState(CopilotKitState):
    pass


class AgentContext(TypedDict, total=False):
    output_schema: dict[str, Any]


agent = create_agent(
    model="openai:gpt-5.5",
    middleware=[
        normalize_context,
        CopilotKitMiddleware(),
        apply_structured_output_schema,
    ],
    context_schema=AgentContext,
    state_schema=AgentState,
    system_prompt=(
        "You are a helpful UI assistant. Build visual responses using the "
        "available components."
    ),
)

app = FastAPI()

add_langgraph_fastapi_endpoint(
    app=app,
    agent=LangGraphAGUIAgent(
        name="copilotkit_shadify",
        description="A UI assistant that returns structured component payloads.",
        # The AG-UI bridge reads graph state, so this route needs a checkpointer.
        graph=agent.copy(update={"checkpointer": MemorySaver()}),
    ),
    path="/",
)

AG-UI 桥接层在每次运行时都会读取图的状态，因此 FastAPI 路由背后的图需要检查点保存器。不要把检查点保存器放在 agent 本身上：agent 同时也列在 graphs 下，而 langgraph dev 会拒绝加载自带检查点保存器的已列出图，因为 LangGraph API 会为已列出的图处理持久化。带 MemorySaver 的副本只服务 FastAPI 路由。它的线程存在于进程内存中，因此重启后不会保留，也不会跨副本共享，更不会出现在部署的线程 API 中。若该路由要承载生产流量，请改为传入持久化的 检查点保存器。

这个自定义应用是关键的扩展点：它挂载 AG-UI FastAPI 桥接层，而不会替换底层的 LangGraph 部署。Node CopilotKit 运行时保持独立；参见 添加 CopilotKit 运行时。

在 Python 中，等效的工作在中间件中完成：规范化 CopilotKit 上下文，并将 output_schema 中的 useAgentContext(...) 转发到模型的结构化输出配置中。Hashbrown 生成的 schema 没有顶层 title，而 OpenAI 集成需要它来命名结构化输出 schema，因此中间件会在缺少时填充 title 和 description。

expandable src/middleware.py 
import json
from collections.abc import Mapping

from langchain.agents.middleware import before_agent, wrap_model_call
from langchain.agents.structured_output import ProviderStrategy


@wrap_model_call
async def apply_structured_output_schema(request, handler):
    schema = None
    runtime = getattr(request, "runtime", None)
    runtime_context = getattr(runtime, "context", None)

    if isinstance(runtime_context, Mapping):
        schema = runtime_context.get("output_schema")

    if schema is None and isinstance(getattr(request, "state", None), dict):
        copilot_context = request.state.get("copilotkit", {}).get("context")
        if isinstance(copilot_context, list):
            for item in copilot_context:
                if isinstance(item, dict) and item.get("description") == "output_schema":
                    schema = item.get("value")
                    break

    if isinstance(schema, str):
        try:
            schema = json.loads(schema)
        except json.JSONDecodeError:
            schema = None

    if isinstance(schema, dict):
        # OpenAI uses the top-level title as the structured output name.
        schema = {
            **schema,
            "title": schema.get("title") or "CopilotKitStructuredOutput",
            "description": schema.get("description")
            or "Structured response schema for the CopilotKit preview.",
        }
        request = request.override(
            response_format=ProviderStrategy(schema=schema, strict=True),
        )

    return await handler(request)


@before_agent
def normalize_context(state, runtime):
    copilotkit_state = state.get("copilotkit", {})
    context = copilotkit_state.get("context")

    if isinstance(context, list):
        normalized = [
            item.model_dump() if hasattr(item, "model_dump") else item
            for item in context
        ]
        return {"copilotkit": {**copilotkit_state, "context": normalized}}

    return None

这样就实现了清晰的关注点分离：

  • LangGraph 仍负责图执行与持久化

  • CopilotKit 负责面向对话的运行时契约

  • 你的自定义端点在一个部署中将两者粘合起来

添加 CopilotKit 运行时#

FastAPI 路由使用 AG-UI 协议，而不是 CopilotKit 运行时协议，因此前端无法直接调用它：将 runtimeUrl 指向 FastAPI 路由会以 runtime_info_fetch_failed 失败。请在一个小型 Node 服务器中运行 CopilotKit 运行时，并将 HttpAgent 指向 FastAPI 路由。Python 图和中间件仍然定义工具行为与智能体逻辑。

server.ts 
import { createServer } from "node:http";

import { HttpAgent } from "@ag-ui/client";
import { CopilotRuntime } from "@copilotkit/runtime/v2";
import { createCopilotNodeListener } from "@copilotkit/runtime/v2/node";

// The FastAPI route is mounted at the root of the LangGraph deployment.
const agentUrl = process.env.LANGGRAPH_DEPLOYMENT_URL || "http://127.0.0.1:2024";

const runtime = new CopilotRuntime({
  agents: {
    default: new HttpAgent({ url: agentUrl }),
  },
});

createServer(
  createCopilotNodeListener({
    runtime,
    basePath: "/api/copilotkit",
    cors: true,
  }),
).listen(4000);

在 LangGraph 部署旁边启动运行时：

bash 
bun server.ts

该运行时在 4000 端口提供 /api/copilotkit。将前端指向它，可以通过设置 VITE_RUNTIME_URL=http://localhost:4000/api/copilotkit，或从你的开发服务器将 /api/copilotkit 代理到 4000 端口。

此运行时是基本的应用内集成。Channels 不使用 FastAPI 路由：它通过部署的 graph API 使用 LangGraphAgent 连接到图。

组织前端应用结构#

在前端，用 CopilotKit 包裹你的应用，并将其指向自定义运行时 URL：

tsx 
import { CopilotKit } from "@copilotkit/react-core";
import { CopilotChat, useAgentContext } from "@copilotkit/react-core/v2";
import { s } from "@hashbrownai/core";

import { useChatKit } from "@/components/chat/chat-kit";
import { chatTheme } from "@/lib/chat-theme";

export function App() {
  return (
    <CopilotKit runtimeUrl={import.meta.env.VITE_RUNTIME_URL ?? "/api/copilotkit"}>
      <Page />
    </CopilotKit>
  );
}

function Page() {
  const chatKit = useChatKit();

  useAgentContext({
    description: "output_schema",
    value: s.toJsonSchema(chatKit.schema),
  });

  return <CopilotChat {...chatTheme} />;
}

这里有两个重要部分：

  • runtimeUrl="/api/copilotkit" 将聊天发送到你的自定义后端路由，而不是直接发送到原始的 LangGraph API

  • useAgentContext(...) 将 UI schema 发送给智能体，使模型知道应生成哪种结构化输出格式

注册动态组件#

组件注册表位于 useChatKit() 中。你可以在这里定义智能体允许输出的组件集合，例如卡片、行、列、图表、代码块和按钮。

tsx 
import { s } from "@hashbrownai/core";
import { exposeComponent, exposeMarkdown, useUiKit } from "@hashbrownai/react";

import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";
import { CodeBlock } from "@/components/ui/code-block";
import { Row, Column } from "@/components/ui/layout";
import { SimpleChart } from "@/components/ui/simple-chart";

export function useChatKit() {
  return useUiKit({
    components: [
      exposeMarkdown(),
      exposeComponent(Card, {
        name: "card",
        description: "Card to wrap generative UI content.",
        children: "any",
      }),
      exposeComponent(Row, {
        name: "row",
        props: {
          gap: s.string("Tailwind gap size") as never,
        },
        children: "any",
      }),
      exposeComponent(Column, {
        name: "column",
        children: "any",
      }),
      exposeComponent(SimpleChart, {
        name: "chart",
        props: {
          labels: s.array("Category labels", s.string("A label")),
          values: s.array("Numeric values", s.number("A value")),
        },
        children: false,
      }),
      exposeComponent(CodeBlock, {
        name: "code_block",
        props: {
          code: s.streaming.string("The code to display"),
          language: s.string("Programming language") as never,
        },
        children: false,
      }),
      exposeComponent(Button, {
        name: "button",
        children: "text",
      }),
    ],
  });
}

该注册表成为智能体与 UI 之间的契约。模型并不是在生成任意的 JSX，而是在生成必须通过你所暴露的组件和 props 校验的结构化数据。

将助手消息渲染为动态 UI#

助手响应到达后，由自定义消息渲染器决定如何显示它。在本示例中：

  • 助手消息会按照 UI kit schema 被解析为结构化 JSON

  • 有效的结构化输出会渲染为真实的 React 组件

  • 用户消息会渲染为普通聊天气泡

tsx 
import type { AssistantMessage } from "@ag-ui/core";
import type { RenderMessageProps } from "@copilotkit/react-ui";
import { useJsonParser } from "@hashbrownai/react";
import { memo } from "react";

import { useChatKit } from "@/components/chat/chat-kit";
import { Squircle } from "@/components/squircle";

const AssistantMessageRenderer = memo(function AssistantMessageRenderer({
  message,
}: {
  message: AssistantMessage;
}) {
  const kit = useChatKit();
  const { value } = useJsonParser(message.content ?? "", kit.schema);

  if (!value) return null;

  return (
    <div className="group/msg mt-2 flex w-full justify-start">
      <div className="magic-text-output w-full px-1 py-1">{kit.render(value)}</div>
    </div>
  );
});

export function CustomMessageRenderer({ message }: RenderMessageProps) {
  if (message.role === "assistant") {
    return <AssistantMessageRenderer message={message} />;
  }

  return (
    <div className="flex w-full justify-end">
      <Squircle className="w-full max-w-[64ch] px-4 py-3">
        <pre>{typeof message.content === "string" ? message.content : JSON.stringify(message.content, null, 2)}</pre>
      </Squircle>
    </div>
  );
}

这种渲染器模式正是该集成显得原生自然的原因：

  • CopilotKit 处理聊天状态与传输

  • 自定义渲染器决定助手负载如何变成 UI

  • Hashbrown 将已校验的结构化数据转换为具体的 React 元素

Channels#

为应用内 copilot 提供支持的同一个智能体，也可以作为 Slack 及其他消息平台中的机器人运行。CopilotKit Channels 通过托管的 CopilotKit Intelligence 连接，将你的 LangChain 智能体连接到消息平台：Intelligence 持有平台凭证与消息投递，而你的进程负责运行智能体。

注意

Channels 需要 @copilotkit/channels 0.6.1 和 @copilotkit/runtime 1.65.0（作为经过测试的一对一起安装），以及运行在长时间主机上的 Node.js 22 或更高版本。该 Channel 所连接的 LangChain 部署可以是 Python 或 TypeScript。

注意

本页展示 Channels 如何与 LangChain 智能体配合。若需以 LangGraph 为后端的完整 Slack 演练，请参阅 在 Slack 中连接并运行你的智能体。其他智能体后端与平台覆盖情况，请参阅 Channels 概览。

各部分如何协同#

CopilotKit Intelligence 持有平台连接（Slack、Microsoft Teams 等）及其凭证。你长期运行的 Channels 监听器持有智能体、工具与应用逻辑。每一轮都遵循相同的路径：

  1. 某人在 Slack 中向你的应用发送消息。

  2. Intelligence 使用为该 Channel 配置的凭证接收平台事件。

  3. 持久的 Intelligence 网关连接将该轮次投递到你的 Channels 监听器。

  4. 监听器通过 AG-UI 运行你的 LangChain 智能体并渲染回复。

  5. Intelligence 将结果以原生 Slack Block Kit 形式发回。

平台凭证永远不会进入智能体进程。在 CopilotKit Intelligence 中创建托管 Channel 并连接 Slack：Intelligence 会存储 Slack 凭证，并为你提供 Channel code（CHANNEL_CODE）和项目级的 Intelligence API key（INTELLIGENCE_API_KEY）供监听器使用。

连接你的 LangChain 智能体#

为每个会话返回一个新的智能体，以线程为键，避免状态在 Slack 线程之间泄漏。LangGraph Server 使用 LangGraph API，因此请使用 @copilotkit/runtime/langgraph 中的 LangGraphAgent，而不是 HttpAgent。将其指向你已运行的 部署：

icon="robot" title="agent.ts" 
import { LangGraphAgent } from "@copilotkit/runtime/langgraph";

// A fresh agent per conversation, keyed by thread.
export function makeAgent(threadId: string) {
  const agent = new LangGraphAgent({
    deploymentUrl: process.env.LANGGRAPH_DEPLOYMENT_URL!,
    graphId: "copilotkit_shadify", // the graph you deployed above
  });
  agent.threadId = threadId;
  return agent;
}

运行 Channel 监听器#

使用来自 Intelligence 的 Code 声明 Channel，并将每条消息转发给智能体。创建 Node 监听器就是连接 Channel 的操作。请在创建监听器之前注册进程清理逻辑，这样在连接窗口期间按下 Ctrl-C 仍能干净地停止 Channel。

icon="server" title="channel.ts" 
import { createServer } from "node:http";

import { createChannel } from "@copilotkit/channels";
import { CopilotKitIntelligence, CopilotRuntime } from "@copilotkit/runtime/v2";
import { createCopilotNodeListener } from "@copilotkit/runtime/v2/node";

import { makeAgent } from "./agent.js";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing required environment variable: ${name}`);
  return value;
}

// `name` must match the Channel Code shown in CopilotKit Intelligence.
const channel = createChannel({
  name: required("CHANNEL_CODE"),
  identifyUser: "platform",
  agent: makeAgent,
});

// Each incoming message starts a turn; runAgent streams the reply back.
channel.onMessage(async ({ thread, message }) => {
  await thread.runAgent({
    prompt: message.contentParts?.length
      ? [
          ...(message.text ? [{ type: "text" as const, text: message.text }] : []),
          ...message.contentParts,
        ]
      : message.text,
    context: [{ description: "Originating platform", value: message.platform }],
  });
});

const intelligence = new CopilotKitIntelligence({
  apiKey: required("INTELLIGENCE_API_KEY"),
});

const runtime = new CopilotRuntime({
  agents: {},
  intelligence,
  channels: [channel],
});

// Wire teardown before the listener exists, because creating it starts the
// Channel. A Ctrl-C during the connect window then still tears it down.
let teardown: (() => Promise<void>) | undefined;
const shutdown = async () => {
  await teardown?.();
};
process.once("SIGINT", shutdown);
process.once("SIGTERM", shutdown);

const listener = createCopilotNodeListener({
  runtime,
  basePath: "/api/copilotkit",
});
const channels = listener.channels;
const server = createServer(listener);
teardown = async () => {
  await channels.stop();
  if (server.listening) server.close();
};

// Creating the listener starts the Channel; there is no `channel.start()`.
// `ready()` is optional; inspect `status()` before reporting the Channel online.
await channels.ready({ timeoutMs: 30_000 });
if (channels.status().overall !== "online") {
  throw new Error("Slack Channel is not online");
}

const port = Number(process.env.PORT ?? 3000);
server.listen(port, () => {
  console.log(`Slack Channel online; listening on :${port}`);
});

设置运行时密钥，然后启动进程：

INTELLIGENCE_API_KEY=<project-api-key>
CHANNEL_CODE=support-slack
LANGGRAPH_DEPLOYMENT_URL=http://127.0.0.1:2024
PORT=3000
node --env-file=.env --import tsx channel.ts

进程连接后，Channel 在 Intelligence 中会从 Waiting for runtime 变为 Online。

最佳实践#

  • 保持自定义端点轻量： 用它来适配 CopilotKit 与你的图部署，而不是复制图内部已有的业务逻辑

  • 显式发送 schema： 每次页面挂载时，useAgentContext 都应描述 UI 契约

  • 注册受限的组件集合： 只暴露你确实希望模型使用的组件和 props

  • 将渲染视为解析步骤： 在渲染前按照 schema 解析助手内容

  • 保持用户消息简单： 只有助手消息需要结构化渲染器；用户消息可以保持普通聊天气泡
