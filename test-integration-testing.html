集成测试

使用真实 LLM API 测试智能体：组织测试、管理密钥、处理结果不稳定性并控制成本。
约 6 分钟 社区翻译 查看英文原文 ↗

集成测试用于验证你的智能体能否与模型 API 和外部服务正确协作。与使用伪造对象和 mock 的 单元测试不同，集成测试会发起真实的网络调用，以确认各组件能够协同工作、凭据有效且延迟可接受。

由于 LLM 的响应具有不确定性，集成测试需要采用不同于传统软件测试的策略。本指南介绍如何组织、编写和运行智能体的集成测试。如果你要为 LangChain 本身贡献代码并了解通用的测试基础设施，请参阅 为代码做贡献。

分离单元测试与集成测试#

集成测试速度更慢且需要 API 凭据，因此应与单元测试分开。这样可以每次变更都运行快速的单元测试，而把集成测试留给 CI 或部署前检查。

使用 pytest 标记为集成测试打标签：

python 
import pytest
from langchain.agents import create_agent
from langchain.messages import HumanMessage

@pytest.mark.integration
def test_agent_with_real_model():
    agent = create_agent("claude-sonnet-4-6", tools=[get_weather])
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in SF?")]
    })
    assert len(result["messages"]) > 1

配置 pytest 识别该标记，并在默认运行时排除集成测试：

pytest.ini 
[pytest]
markers =
    integration: tests that call real LLM APIs
addopts = -m "not integration"
pyproject.toml 
[tool.pytest.ini_options]
markers = [
  "integration: tests that call real LLM APIs"
]
addopts = "-m 'not integration'"

显式运行集成测试：

bash 
pytest -m integration

管理 API 密钥#

集成测试需要真实的 API 凭据。应从环境变量中加载它们，以免密钥进入源代码管理。

使用 conftest.py fixture 校验所需的密钥是否可用：

python 
import os
import pytest

@pytest.fixture(autouse=True)
def check_api_keys():
    if not os.environ.get("OPENAI_API_KEY"):
        pytest.skip("OPENAI_API_KEY not set")

本地开发时，将密钥存放在 .env 文件中，并用 python-dotenv 加载它们：

.env 
OPENAI_API_KEY=sk-...
conftest.py 
from dotenv import load_dotenv

load_dotenv()
警告

将 .env 添加到你的 .gitignore 中，避免提交凭据。在 CI 中，通过所用平台的机密管理功能注入密钥（例如 GitHub Actions secrets）。

断言结构，而非内容#

LLM 的响应在每次运行之间都会变化。不要断言精确的输出字符串，而应验证响应的结构性属性：消息类型、工具调用名称、参数形态和消息数量。

python 
from langchain.agents import create_agent
from langchain.messages import AIMessage, HumanMessage

def test_agent_calls_weather_tool():
    agent = create_agent("claude-sonnet-4-6", tools=[get_weather])
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in SF?")]
    })

    messages = result["messages"]
    tool_calls = [
        tc
        for msg in messages
        if hasattr(msg, "tool_calls")
        for tc in (msg.tool_calls or [])
    ]

    assert any(tc["name"] == "get_weather" for tc in tool_calls)
    assert isinstance(messages[-1], AIMessage)
    assert len(messages[-1].content) > 0
提示

如果需要更严格的轨迹断言，可使用 AgentEvals 评估器，它支持 unordered 和 superset 等模糊匹配模式。

降低成本和延迟#

调用 LLM API 的集成测试会产生真实费用。以下做法有助于让测试套件保持快速且成本可控：

  • 使用更小的模型：对于只需验证工具调用和响应结构的测试，可使用 gemini-3.1-flash-lite 或同等模型。

  • 设置 maxTokens：限制响应长度，避免冗长且昂贵的补全。

  • 限制测试范围：每个测试只验证一种行为。当单轮测试足够时，避免使用串联多次 LLM 调用的端到端场景。

  • 有选择地运行：利用 上文 中的测试分离方式，仅在 CI 或部署前运行集成测试，而不是每次保存文件都运行。

python 
from langchain.agents import create_agent

agent = create_agent(
    "gemini-3.1-flash-lite",
    tools=[get_weather],
    model_kwargs={"max_tokens": 256},
)

录制并回放 HTTP 调用#

对于在 CI 中频繁运行的测试，可以在首次运行时录制 HTTP 交互，并在后续运行中回放，而无需发起真实 API 调用。这样在初次录制之后即可消除成本和延迟。

vcrpy 会将 HTTP 请求/响应对记录到 YAML“cassette”文件中。pytest-recording 插件将其与 pytest 集成。

配置你的 conftest.py 以从 cassette 中过滤敏感信息：

conftest.py 
import pytest

@pytest.fixture(scope="session")
def vcr_config():
    return {
        "filter_headers": [
            ("authorization", "XXXX"),
            ("x-api-key", "XXXX"),
        ],
        "filter_query_parameters": [
            ("api_key", "XXXX"),
            ("key", "XXXX"),
        ],
    }

配置你的项目识别 vcr 标记：

pytest.ini 
[pytest]
markers =
    vcr: record/replay HTTP via VCR
addopts = --record-mode=once
pyproject.toml 
[tool.pytest.ini_options]
markers = [
  "vcr: record/replay HTTP via VCR"
]
addopts = "--record-mode=once"
注意

--record-mode=once 选项会在首次运行时录制 HTTP 交互，并在后续运行中回放。

使用 vcr 标记装饰你的测试：

python 
import pytest
from langchain.agents import create_agent
from langchain.messages import HumanMessage

@pytest.mark.vcr()
def test_agent_trajectory():
    agent = create_agent("claude-sonnet-4-6", tools=[get_weather])
    result = agent.invoke({
        "messages": [HumanMessage(content="What's the weather in SF?")]
    })
    assert any(
        tc["name"] == "get_weather"
        for msg in result["messages"]
        if hasattr(msg, "tool_calls")
        for tc in (msg.tool_calls or [])
    )

首次运行会发起真实的网络调用，并在 tests/cassettes/ 中生成 cassette 文件。后续运行会回放已录制的响应。

警告

当你修改提示词、添加新工具或更改预期轨迹时，已保存的 cassette 会过时，现有测试 将会失败。请删除对应的 cassette 文件并重新运行测试，以录制新的交互。
