分支对话

通过从检查点分叉来编辑消息并重新生成响应
约 5 分钟 社区翻译 查看英文原文 ↗

与 AI 智能体的对话很少是线性的。你可能想要重新表述一个问题、重新生成一个你不满意的响应，或探索不同的对话路径而不丢失检查点历史。分支对话使用 LangGraph 检查点作为分叉点：每次编辑或重新生成都会从所选消息的父检查点提交一次新的运行。

注意

此功能需要 LangGraph Agent Server。请在本地使用 langgraph dev 运行你的智能体，或 将其部署到 LangSmith 以使用此模式。

什么是分支对话？#

分支对话将对话视为一条带检查点的时间线，而不是一个扁平列表。每条消息都带有元数据，指向该消息创建之前的检查点。编辑消息或重新生成响应时，会从该检查点提交一次新的运行。

核心能力：

  • 编辑任意用户消息：重写之前的提示词，并从该位置重新运行智能体

  • 重新生成任意 AI 响应：让智能体针对同一输入生成不同的回答

  • 查看历史：当你需要分支时间线时，使用 LangGraph 客户端加载检查点

设置流元数据#

使用根流获取消息，然后在渲染每条消息的组件中读取逐消息的检查点元数据。元数据中包含用于分叉的父检查点 ID。

注意

代码示例使用 useStream<typeof myAgent> 以获得类型安全的流状态。关于类型推断，请参阅 Python 或 JavaScript 后端。

React 
import { useStream } from "@langchain/react";

const AGENT_URL = "http://localhost:2024";

export function Chat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: AGENT_URL,
    assistantId: "simple_agent",
  });

  return (
    <div>
      {stream.messages.map((msg) => (
        <MessageWithForkControls key={msg.id} stream={stream} message={msg} />
      ))}
    </div>
  );
}

了解消息元数据#

useMessageMetadata(stream, messageId) 辅助函数会为单条消息返回 MessageMetadata。请在渲染每条消息的组件中使用它，使元数据的作用域限定在该消息 ID 上：

tsx 
import type { BaseMessage } from "langchain";
import { useState } from "react";
import { useMessageMetadata, useStream } from "@langchain/react";

function Chat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: AGENT_URL,
    assistantId: "simple_agent",
  });

  return stream.messages.map((message) => (
    <MessageWithForkControls
      key={message.id}
      stream={stream}
      message={message}
    />
  ));
}

function MessageWithForkControls({
  stream,
  message,
}: {
  stream: ReturnType<typeof useStream>;
  message: BaseMessage;
}) {
  const metadata = useMessageMetadata(stream, message.id);
  const checkpointId = metadata?.parentCheckpointId;
  const [editedText, setEditedText] = useState(message.text);

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        if (!checkpointId) return;

        stream.submit(
          { messages: [{ type: "human", content: editedText }] },
          { forkFrom: checkpointId }
        );
      }}
    >
      <textarea
        value={editedText}
        onChange={(event) => setEditedText(event.target.value)}
      />
      <button disabled={!checkpointId || editedText === message.text}>
        Submit edited branch
      </button>
    </form>
  );
}

parentCheckpointId 是消息之前的检查点。将它用作编辑和重新生成的分叉点。

编辑消息#

要编辑用户消息并对对话进行分叉：

  1. 从消息的元数据中获取 parentCheckpointId

  2. 使用 forkFrom: checkpointId 提交编辑后的消息

  3. 智能体从该位置重新运行

typescript 
function handleEdit(
  stream: ReturnType<typeof useStream>,
  originalMsg: HumanMessage,
  metadata: MessageMetadata | undefined,
  newText: string
) {
  if (!metadata?.parentCheckpointId) return;

  stream.submit(
    {
      messages: [{ type: "human", content: newText }],
    },
    { forkFrom: metadata.parentCheckpointId }
  );
}

编辑之后：

  • 智能体使用更新后的消息从分叉点重新运行

  • 原始路径仍保留在线程历史中

重新生成响应#

要在不更改输入的情况下重新生成 AI 响应：

  1. 从 AI 消息的元数据中获取 parentCheckpointId

  2. 使用 undefined 输入和 forkFrom: checkpointId 提交

  3. 智能体从该位置生成新的响应

typescript 
function handleRegenerate(
  stream: ReturnType<typeof useStream>,
  metadata: MessageMetadata | undefined
) {
  if (!metadata?.parentCheckpointId) return;

  stream.submit(undefined, {
    forkFrom: metadata.parentCheckpointId,
  });
}

SDK 会将 undefined 输入转换为 null，以便从检查点继续执行而无需提供新输入。空对象（{}）则提供新输入。每次重新生成都会在同一线程中创建一条新路径。

警告

重新生成可能会重新执行下游工具和 API 调用。它不会撤销原始运行产生的外部影响。重新生成前请检查这些影响。

提示

重新生成对非确定性智能体很有用。由于 LLM 输出会随温度变化，重新生成相同的提示词通常会产生明显不同的响应。

分支的底层工作原理#

LangGraph 在超级步边界将状态持久化为 检查点。在同一超级步中并行运行的节点共享一个检查点边界。当你使用 forkFrom 提交时，后端会从该点开始一条新的执行路径，而不是追加到当前对话。结果是一棵树状结构：

text 
User: "What is React?"
  └─ AI: "React is a JavaScript library..." (branch A)
  └─ AI: "React is a UI framework..." (branch B, regenerated)

User: "Tell me about hooks" (branch A)
  └─ AI: "Hooks are functions..."

User: "Tell me about JSX" (edited from branch A)
  └─ AI: "JSX is a syntax extension..."

每条路径都会持久化到检查点存储中。当你需要跨检查点构建单独的时间线视图时，使用 stream.client.threads.getHistory(threadId)。历史记录按最新优先排列，默认返回 10 条。使用每个状态的 parent_checkpoint 重建祖先关系；仅凭列表位置无法识别分支。

最佳实践#

  • 在消息附近读取元数据：在渲染消息控件的组件中调用 useMessageMetadata。

  • 悬停时显示分叉控件：编辑和重新生成按钮应在悬停时出现，以保持 UI 简洁。

  • 按需刷新历史：仅在渲染时间线或分叉结束后调用 client.threads.getHistory()。

  • 流式传输期间禁用控件：智能体正在主动流式输出响应时，不允许编辑或重新生成。启用这些操作前请检查 stream.isLoading。

  • 取消时保留编辑文本：如果用户开始编辑后取消，请将文本区域重置为原始消息内容。

  • 使用深层检查点树进行测试：频繁编辑和重新生成的用户可能会创建大量路径。确保时间线渲染保持良好性能。
