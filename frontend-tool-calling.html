工具调用

使用丰富且类型安全的 UI 卡片展示智能体的工具调用
约 6 分钟 社区翻译 查看英文原文 ↗

智能体可以调用外部工具，例如天气 API、计算器、网页搜索、数据库查询等。其结果以原始 JSON 形式返回。本模式展示如何为智能体的每一次工具调用渲染结构化、类型安全的 UI 卡片，并完整处理加载状态与错误。

工具调用的工作方式#

当 LangGraph 智能体判断需要外部数据时，它会在一条 AI 消息中发出一个或多个 工具调用。每次工具调用都包含：

  • name：被调用的工具（例如 "get_weather"、"calculator"）

  • args：传给该工具的结构化参数

  • id：用于把调用与其结果关联起来的唯一标识符

智能体运行时执行该工具，结果以 ToolMessage 的形式返回。useStream hook 将这一切统一为一个可直接渲染的 toolCalls 数组。

配置 useStream#

第一步是把 useStream 接入你的智能体后端。该 hook 返回响应式状态，其中包含一个 toolCalls 数组，会随智能体流式输出实时更新。

注意

代码示例使用 useStream<typeof myAgent> 来实现类型安全的流状态。参见针对 Python 或 JavaScript 后端的类型推断。

React 
import { useStream } from "@langchain/react";

const AGENT_URL = "http://localhost:2024";

export function Chat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: AGENT_URL,
    assistantId: "tool_calling",
  });

  return (
    <div>
      {stream.messages.map((msg) => (
        <Message key={msg.id} message={msg} toolCalls={stream.toolCalls} />
      ))}
    </div>
  );
}
Vue

AssembledToolCall 类型#

toolCalls 数组中的每一项都是一个 AssembledToolCall 对象：

typescript 
interface AssembledToolCall<
  TName extends string = string,
  TInput = unknown,
  TOutput = unknown,
> {
  name: TName;
  callId: string;
  id: string;
  namespace: string[];
  input: TInput;
  args: TInput;
  output: TOutput | null;
  status: "running" | "finished" | "error";
  error: string | undefined;
}
属性说明
name工具的名称（例如 "get_weather"）
callId与该 AI 消息中 tool_calls 条目匹配的唯一 ID
idcallId 的别名，与消息级工具调用相匹配
namespace发出该工具调用的命名空间
input智能体传给该工具的结构化参数
argsinput 的别名，与消息级工具调用相匹配
output调用成功后的工具输出；运行中或出错后为 null
status生命周期状态："running"、"finished" 或 "error"
error工具调用失败时的错误详情

按消息过滤工具调用#

一条 AI 消息可能触发多次工具调用，而你的对话中也可能包含多条 AI 消息。要在每条消息下渲染正确的工具卡片，可将 callId 与该消息的 tool_calls 数组进行匹配来过滤：

tsx 
function Message({
  message,
  toolCalls,
}: {
  message: AIMessage;
  toolCalls: AssembledToolCall[];
}) {
  const messageToolCalls = toolCalls.filter((tc) =>
    message.tool_calls?.find((t) => t.id === tc.callId)
  );

  return (
    <div>
      <p>{message.text}</p>
      {messageToolCalls.map((tc) => (
        <ToolCard key={tc.callId} toolCall={tc} />
      ))}
    </div>
  );
}

构建专用工具卡片#

与其直接抛出原始 JSON，不如为每个工具构建专用的 UI 组件。使用 name 来选择正确的卡片：

tsx 
function ToolCard({ toolCall }: { toolCall: AssembledToolCall }) {
  if (toolCall.status === "running") {
    return <LoadingCard name={toolCall.name} />;
  }

  if (toolCall.status === "error") {
    return <ErrorCard name={toolCall.name} error={toolCall.error} />;
  }

  switch (toolCall.name) {
    case "get_weather":
      return <WeatherCard input={toolCall.input} output={toolCall.output} />;
    case "calculator":
      return (
        <CalculatorCard input={toolCall.input} output={toolCall.output} />
      );
    case "web_search":
      return <SearchCard input={toolCall.input} output={toolCall.output} />;
    default:
      return <GenericToolCard toolCall={toolCall} />;
  }
}

加载与错误状态#

始终处理 pending 和 error 状态，为用户提供清晰的反馈：

tsx 
function LoadingCard({ name }: { name: string }) {
  return (
    <div className="flex items-center gap-2 rounded-lg border p-4 animate-pulse">
      <Spinner />
      <span>Running {name}...</span>
    </div>
  );
}

function ErrorCard({ name, error }: { name: string; error?: unknown }) {
  return (
    <div className="rounded-lg border border-red-300 bg-red-50 p-4">
      <h3 className="font-semibold text-red-700">Error in {name}</h3>
      <p className="text-sm text-red-600">
        {String(error ?? "Tool execution failed")}
      </p>
    </div>
  );
}

类型安全的工具参数#

如果你的工具使用结构化 schema 定义，就可以使用 ToolCallFromTool 工具类型获得完全类型化的 args：

typescript 
import { tool } from "@langchain/core/tools";
import { z } from "zod";

const getWeather = tool(async ({ location }) => { /* ... */ }, {
  name: "get_weather",
  description: "Get the current weather for a location",
  schema: z.object({
    location: z.string().describe("City name"),
  }),
});

type WeatherToolCall = ToolCallFromTool<typeof getWeather>;
// WeatherToolCall.input and WeatherToolCall.args are now { location: string }
提示

使用 ToolCallFromTool 可获得编译期安全。一旦工具 schema 发生变化，你的 UI 组件会立即标出类型错误。

将工具调用与流式文本内联渲染#

工具调用常常与流式文本交错到达。useStream hook 会让 toolCalls 与流保持同步，因此智能体一发出调用、工具尚未执行完成时，加载中的卡片就会立即出现。

这意味着用户会看到：

  1. AI 的文本随流式输出逐步呈现

  2. 工具调用一发出就出现的加载卡片

  3. 工具完成后卡片更新并显示结果

注意

工具调用就地更新。同一个 callId 会从 "running" 变为 "finished"（或 "error"），因此你的 UI 会用新状态重新渲染同一个组件。

处理多个并发工具调用#

智能体可以并行调用多个工具。toolCalls 数组中会同时包含多个带有 status: "running" 的条目。每一项独立完成，因此你的 UI 应妥善处理部分完成的情况：

tsx 
function ToolCallList({ toolCalls }: { toolCalls: AssembledToolCall[] }) {
  const pending = toolCalls.filter((tc) => tc.status === "running");
  const completed = toolCalls.filter((tc) => tc.status === "finished");

  return (
    <div className="space-y-2">
      {completed.map((tc) => (
        <ToolCard key={tc.callId} toolCall={tc} />
      ))}
      {pending.map((tc) => (
        <LoadingCard key={tc.callId} name={tc.name} />
      ))}
    </div>
  );
}

最佳实践#

构建工具调用 UI 时请遵循以下准则：

  • 始终处理全部三种状态：running、finished 和 error。用户绝不应看到空白卡片。

  • 安全地校验结果。在针对特定卡片收窄类型之前，工具输出的类型为 unknown。

  • 提供通用回退方案。并非每个工具都需要专属卡片。对于未知的工具名称，渲染一个可折叠的 JSON 视图。

  • 在加载时显示工具名称与参数。即使在结果返回之前，用户也希望知道智能体在做什么。

  • 保持卡片紧凑。工具卡片与聊天消息内联排列。避免使用过大的组件让对话内容显得拥挤。
