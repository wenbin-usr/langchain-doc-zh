断开与重连流

断开并重新连接到运行中的智能体流
约 5 分钟 社区翻译 查看英文原文 ↗

加入与重新加入让你可以在不停止智能体的情况下断开与运行中的智能体流的连接，之后再重新连接。客户端离开期间，智能体仍在服务端继续执行，而你则可以从上次中断的地方精确地继续接收流。

注意

此功能需要 LangGraph Agent Server。要使用此模式，可在本地用 langgraph dev 运行智能体，或将其部署到 LangSmith。

为什么需要加入与重新加入？#

传统的流式传输 API 将客户端与服务端紧密耦合：客户端一旦断开，流就会丢失。加入与重新加入打破了这种耦合，从而支持几种重要的模式：

  • 网络中断：移动用户在蜂窝基站或 Wi-Fi 网络之间切换时可以无缝恢复

  • 页面导航：用户离开聊天页面后再返回，不会丢失进度

  • 移动端进入后台：被操作系统挂起的应用在回到前台时可以重新加入流

  • 长时间运行的任务：智能体执行耗时数分钟的操作（研究、代码生成、数据分析）时，用户无需一直保持页面打开

  • 多设备交接：在手机上开始对话，在桌面端重新加入

核心概念#

加入/重新加入模式涉及三个关键机制：

方法 / 选项用途
threadId将流绑定到要观测的 LangGraph 线程
onThreadId持久化新建的线程 ID，以便重新挂载时可以重新连接
stream.disconnect()在客户端离开流，同时智能体继续在服务端运行
使用相同的 threadId 重新挂载重新附加到该线程正在进行中的工作
注意

加入/重新加入使用 stream.disconnect()，而不是 stream.stop()。默认情况下，stream.stop() 会取消当前活动运行：它既断开客户端又在服务端取消该运行。要进行加入/重新加入，请调用 stream.disconnect()（stop({ cancel: false }) 的别名），这样在你离开期间智能体仍会继续处理。

要从应用代码中显式取消执行，请使用 stream.stop() 或 client.runs.cancel。

设置 useStream#

关键的设置步骤是持久化 threadId。当组件使用相同的线程 ID 重新挂载时，流会附加到该线程的当前状态以及任何正在进行的运行。

注意

代码示例使用 useStream<typeof myAgent> 实现类型安全的流状态。参见针对 Python 或 JavaScript 后端的类型推断。

React 
import { useStream } from "@langchain/react";
import { useCallback, useState } from "react";

function Chat() {
  const [connected, setConnected] = useState(true);
  const [mountKey, setMountKey] = useState(0);
  const [threadId, setThreadId] = useState<string | null>(
    () => sessionStorage.getItem("activeThreadId"),
  );

  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "join_rejoin",
    threadId,
    onThreadId(id) {
      setThreadId(id);
      if (id) sessionStorage.setItem("activeThreadId", id);
    },
  });

  const disconnect = useCallback(() => {
    void stream.disconnect();
    setConnected(false);
  }, [stream]);

  const rejoin = useCallback(() => {
    setMountKey((key) => key + 1);
    setConnected(true);
  }, []);

  return (
    <div key={mountKey}>
      <ConnectionStatus connected={connected} />
      <MessageList messages={stream.messages} />
      <ChatControls
        stream={stream}
        threadId={threadId}
        connected={connected}
        onDisconnect={disconnect}
        onRejoin={rejoin}
      />
    </div>
  );
}

import { useStream } from "@langchain/vue";
import { ref } from "vue";

const connected = ref(true);
const mountKey = ref(0);
const threadId = ref<string | null>(sessionStorage.getItem("activeThreadId"));

  connected.value = true;

Angular 
import { Component, signal } from "@angular/core";
import { injectStream } from "@langchain/angular";

@Component({
  selector: "app-chat",
  template: `
    <connection-status [connected]="connected()" />
    <message-list [messages]="stream.messages()" />
    <chat-controls
      [stream]="stream"
      [threadId]="threadId()"
      [connected]="connected()"
      (disconnect)="disconnect()"
      (rejoin)="rejoin()"
    />
  `,
})
export class ChatComponent {
  threadId = signal<string | null>(sessionStorage.getItem("activeThreadId"));
  connected = signal(true);
  mountKey = signal(0);

  stream = injectStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "join_rejoin",
    threadId: this.threadId,
    onThreadId: (id) => {
      this.threadId.set(id);
      if (id) sessionStorage.setItem("activeThreadId", id);
    },
  });

  disconnect() {
    void this.stream.disconnect();
    this.connected.set(false);
  }

  rejoin() {
    this.mountKey.update((key) => key + 1);
    this.connected.set(true);
  }
}

提交消息#

正常提交消息即可。正是线程 ID 的绑定，使后续的重新挂载能够重新连接到同一对话：

typescript 
stream.submit({ messages: [{ type: "human", content: text }] });

断开与流的连接#

调用 stream.disconnect() 离开流而不取消运行。智能体会继续在服务端处理。

typescript 
await stream.disconnect();
// equivalent to: await stream.stop({ cancel: false })

此处不要使用 stream.stop() —— 它默认会在服务端取消运行。

调用 disconnect() 之后：

  • stream.isLoading 变为 false

  • 你自己的 connected 标志也应变为 false

  • 消息列表会保留截至断开时刻收到的所有消息

  • 智能体继续在服务端运行

  • 在重新加入之前不会收到新消息

重新加入流#

使用保存的线程 ID 重新挂载流消费组件即可重新连接。在 React 中，示例会递增一个 mountKey；在其他框架中，请使用等效的重新挂载或条件渲染模式：

typescript 
setMountKey((key) => key + 1);
setConnected(true);

重新加入之后：

  • connected 变为 true

  • 断开期间生成的任何消息都会被送达

  • 新的流式消息恢复实时传输

  • 如果智能体仍在运行，stream.isLoading 会变为 true；如果它已经结束，你会立即收到最终状态

最佳实践#

  • 加入/重新加入用 disconnect()，取消用 stop()：离开页面或应用进入后台时应调用 stream.disconnect()。面向用户的“停止”或“取消”按钮应调用 stream.stop()（或 client.runs.cancel）。

  • 始终保存线程 ID：没有它就无法重新加入。为增强可靠性，请同时使用组件状态和持久化存储。

  • 显示清晰的连接状态：用户应始终知道自己是正在接收实时更新，还是在查看快照。

  • 在可见性变化时自动重新加入：使用 Page Visibility API 在用户返回到标签页时自动重新加入。

  • 设置合理的超时：如果重新加入尝试耗时过长，则回退为获取线程历史记录。

  • 清理过期线程：当用户重新开始或后端报告该线程不可用时，移除已持久化的线程 ID。
