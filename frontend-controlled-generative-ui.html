受控生成式 UI

使用你编写的组件渲染智能体输出：组件即工具、工具调用渲染、状态渲染与推理
约 2 分钟 社区翻译 查看英文原文 ↗

概述#

受控生成式 UI 位于生成式 UI 谱系中由作者控制的一端。你编写组件，智能体决定渲染哪一个组件以及向其中传入什么数据。智能体从不生成标记：它只从你构建并测试过的一组固定界面中做选择。

在所有生成式 UI 方案中，这种模式的可预测性最高。由于每个组件都出自你的代码库，你可以精确控制品牌、布局、无障碍和交互行为，并能保证智能体呈现的任何内容都已通过你的审核。代价是工程成本：每项新能力都需要你预先编写组件。你的组件库就是边界：智能体只能渲染你已交付的内容。

何时使用这种方法#

在你流量最高、品牌关键的界面上采用受控生成式 UI，这些界面的输出集合是预先已知的，且正确性比新颖性更重要：表单、确认流程，以及任何有严格品牌或无障碍要求的界面。当智能体需要组合你未曾预料到的布局、覆盖大量长尾的次要交互时，请沿谱系再往前一步，改用声明式生成式 UI。

受控生成式 UI 涵盖四项技术，从智能体选定整个界面开始，到前端响应智能体内部状态结束。

组件即工具#

你像暴露工具一样把 UI 组件暴露给智能体。每个组件都有名称、描述和一组有类型的属性，智能体选择一个组件并在响应中提供其数据。前端将智能体的选择映射到你的真实实现。这让智能体的职责保持很小——决定哪个预先批准的界面适合当前场景——而你的代码掌控它外观与行为的一切。

CopilotKit 将这种模式记录为组件即工具。

工具调用渲染#

当智能体调用工具时，该调用会经历一个生命周期：先是待处理，然后完成或失败。工具调用渲染将每个阶段转化为专门构建的 UI，例如搜索运行时的加载卡片、返回时的结果卡片，以及失败时的错误状态，而不是展示原始 JSON。这让智能体的操作清晰可读，让用户对正在发生的事情有信心。

参见工具调用模式。

状态渲染#

智能体在消息列表之外暴露持久、有类型的状态：待办事项、流水线输出、引用、沙箱文件、指标和自定义业务对象。状态渲染将你的组件绑定到该状态，使 UI 成为智能体工作的实时视图，而不是一份对话记录。随着智能体更新状态，界面也随之更新。

参见前端概览中的有类型的智能体状态。若要将单个有类型的响应负载映射到自定义 UI，参见结构化输出。

推理#

具备扩展思考能力的模型会产生独立于最终答案的推理内容。渲染推理内容可以向用户展示智能体如何得出结论，这有助于建立信任、辅助调试并支持审计。你可以控制推理内容出现的方式和时机，例如放在与响应分开的可折叠块中。

参见推理令牌模式。
