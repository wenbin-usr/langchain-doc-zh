MCP 连接

LangChain 中 MCP 的连接生命周期、多服务器、部署扩展、协议代际与缓存。
约 8 分钟 社区翻译 查看英文原文 ↗
注意

langchain.mcp 命名空间需要 langchain[mcp]>=1.4.0，且处于 beta 阶段。API 可能发生变化。

MCPAdapter 会打开一个 MCP 连接、发现工具，并返回你的智能体可以调用的 LangChain 工具。服务器该如何传入，以及适配器需要保持打开多久，取决于你的应用形态。连接本身由 FastMCP 提供；本页介绍 LangChain 中的模式，传输与客户端细节则链接到 FastMCP 文档。

除非你要连接多个服务器或部署大量并发运行，否则优先使用默认生命周期。关于单个目标可以是什么（URL、脚本路径、进程内服务器），参见传输。

选择一种模式#

从每个表格中选择一行。服务器形态与连接生命周期相互独立；任意形态都可以搭配任意生命周期。

连接生命周期#

MCPAdapter 是一个异步上下文管理器。进入它会连接底层客户端，退出它会释放连接。工具发现发生在上下文内部，但它返回的工具持有该客户端，因此在上下文退出后仍然可以调用。

要发现工具并构建智能体（默认模式）：

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter


async def build_agent(target):
    # Discover and build the agent inside the adapter's context. The tools hold
    # the client, so the agent stays usable after the context exits.
    async with MCPAdapter(target) as adapter:
        tools = await adapter.list_tools()
        return create_agent("claude-sonnet-5", tools)

你不需要在整个智能体生命周期内保持适配器打开。除非你要保持会话打开或扩展部署，否则优先使用此模式。

每次调用一个会话#

MCPAdapter 返回的工具是可重入的：每次调用工具时，它都会打开客户端、执行 MCP 调用并释放客户端，无论其他位置是否已经持有连接。因此一次智能体运行会为每次工具调用打开一个会话，并在调用返回时关闭它，而不是在整个运行期间保持会话打开。这可以避免长时间运行的智能体在工具调用之间一直占用空闲连接，也正是工具在发现上下文退出后仍可调用的原因。

如果你希望在一次运行中的多次调用之间保持会话打开，请在调用智能体时保持适配器的上下文打开。可重入客户端会复用已有连接，而不是再打开一个连接。

多个服务器#

要让一个智能体使用多个服务器的工具，当一条聚合连接就足够时选择MCPConfig；当每个服务器都需要自己的连接时（不同的协议代际、按服务器区分的认证，或按客户端配置的共享连接池）选择ClientGroup。

使用 MCPConfig 建立一条聚合连接#

给适配器传入一个 MCPConfig 字典，即可通过一个聚合端点连接多个服务器。FastMCP 会为每个工具加上其配置键作为前缀，因此暴露相同工具名的两个服务器在传给模型的列表中仍可区分：

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter

CONFIG = {
    "mcpServers": {
        "weather": {"command": "python", "args": ["/path/to/weather_server.py"]},
        "calc": {"command": "python", "args": ["/path/to/calc_server.py"]},
    }
}


async def fleet_agent(config):
    async with MCPAdapter(config) as adapter:
        # Every tool is prefixed with its config key (`weather_...`, `calc_...`),
        # so two servers exposing the same tool name stay distinguishable.
        tools = await adapter.list_tools()
        return create_agent("claude-sonnet-5", tools)

每个后端都独立寻址，因此一个服务器集群可以混用不同传输方式：一个服务器走 stdio，另一个走 HTTP。不过，MCPConfig 集群会在所有后端之间共享同一个协商出的协议代际：一旦加入只支持旧版协议的服务器，整个集群就会降到旧版代际。

使用 ClientGroup 建立独立连接#

要让每个服务器使用各自的连接，传入ClientGroup。每个成员都保留自己协商的协议代际、认证和处理程序，该组会把每次调用路由回广播该工具的客户端。这正是旧版服务器与现代服务器可以并存的原因，它也以相同方式为工具划分命名空间，因此不同服务器上相同的工具名永远不会冲突：

python 
from fastmcp.client import Client
from fastmcp.client.group import ClientGroup
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter


async def agent_from_group(legacy_url: str, modern_url: str):
    # One connection per server: a `ClientGroup` keeps each server on its own
    # negotiated protocol era, so a legacy and a modern server run side by side.
    # It also namespaces every tool as `{server}_{tool}`, so two servers exposing
    # the same tool name stay distinct.
    group = ClientGroup(
        {
            "weather": Client(legacy_url, mode="legacy"),
            "calc": Client(modern_url, mode="auto"),
        }
    )
    async with MCPAdapter(group) as adapter:
        tools = await adapter.list_tools()
        return create_agent("claude-sonnet-5", tools)

扩展部署#

服务大量运行的部署应当在每次运行时执行发现，但在底层复用连接，而不是每个请求都重新连接。在 langgraph dev 图工厂中构建智能体，使每次运行都能获取当前的工具目录，并让共享连接池和响应缓存来分摊开销：

python 
SERVERS = {
    "weather": "http://localhost:8001/mcp",
    "calc": "http://localhost:8002/mcp",
}


async def make_graph():
    """Build an agent over an MCP fleet. Called once per run by `langgraph dev`."""
    config = {"mcpServers": {name: {"url": url} for name, url in SERVERS.items()}}
    # A long-lived deployment discovers per run, but reuses one HTTP connection
    # pool underneath. `cache_mode="use"` serves a cached tool list within the
    # server's TTL instead of re-listing on every run.
    async with MCPAdapter(config) as adapter:
        tools = await adapter.list_tools(cache_mode="use")
        return create_agent("claude-sonnet-5", tools)
注意

在 langgraph dev 图工厂中，带注解的参数类型和返回类型必须能在运行时导入，而不能只在TYPE_CHECKING下可用。langgraph-api 使用typing.get_type_hints()对工厂进行分类；如果某个注解无法解析，它注入的就是 config 字典，而非运行时。

在Agent Server上，将该工厂注册到langgraph.json中，而不是导出一个静态编译的图。来自list_tools()的工具在适配器上下文退出后仍可调用，因此对大多数 MCP 配置而言，发现工具后直接返回智能体即可。当你需要在运行前后进行清理，或用execution_runtime在读取 schema 和状态时跳过开销较大的 MCP 工作时，请使用上下文管理器工厂。

如需完整的部署示例，包括为每个调用者签发令牌的按用户认证，请参阅认证。

共享连接池#

默认情况下，每个 FastMCP 客户端管理自己的 HTTP 连接。在一个服务器集群中或存在大量并发运行时，这意味着会有许多相互独立的连接池。要共享同一个连接池，传入一个基于单一传输的 httpx_client_factory，并在不让任何客户端关闭它的情况下将其借出：

python 
import httpx2
from fastmcp.client import Client
from fastmcp.client.group import ClientGroup
from fastmcp.client.transports import StreamableHttpTransport
from langchain.mcp import MCPAdapter

# One connection pool, shared by every server the deployment talks to.
_POOL = httpx2.AsyncHTTPTransport()


class _SharedPool(httpx2.AsyncBaseTransport):
    """Lend `_POOL` to each client without letting any client close it."""

    handle_async_request = _POOL.handle_async_request

    async def aclose(self) -> None: ...


def _client_factory(**kwargs: object) -> httpx2.AsyncClient:
    return httpx2.AsyncClient(transport=_SharedPool(), **kwargs)


async def load_over_shared_pool(servers: dict[str, str]) -> list:
    # Every client draws HTTP connections from the same pool, so a fleet of
    # servers does not each open its own.
    group = ClientGroup(
        {
            name: Client(
                StreamableHttpTransport(url, httpx_client_factory=_client_factory)
            )
            for name, url in servers.items()
        }
    )
    async with MCPAdapter(group) as adapter:
        return await adapter.list_tools()

由于每个客户端都从_POOL借用连接，部署会为整个集群打开一组 HTTP 连接，而不是为每个服务器各开一组。

缓存#

FastMCP 可以缓存 list_tools 的结果，使重复的发现操作免去一次网络往返。缓存需要显式启用，并遵循服务器自身的缓存提示，因此只对声明了这些提示的新版协议服务器生效。

list_tools() 接受一个 cache_mode，用于选择发现操作如何读取已配置的缓存：

  • use（默认值）：当已存在缓存的工具列表且仍在服务器的 TTL 提示范围内时，直接返回该列表，否则获取并存储。

  • refresh：从服务器获取一份最新列表并重新填充缓存。

  • bypass：完全跳过缓存。

python 
tools = await adapter.list_tools(cache_mode="refresh")

缓存及其按主体隔离的配置通过 Client(cache=...) 在客户端本身上完成。如需在一组副本之间共享存储，或按用户划分缓存响应，请参阅 FastMCP 文档中的响应缓存。

协议代际#

MCP 改变了客户端与服务器就各自支持的能力达成一致的方式。legacy 时代以 initialize 握手开启每一次连接；modern 时代（协议版本 2026-07-28 及之后）则通过探测服务器的 server/discover 端点来发现支持情况。FastMCP 会按连接协商时代，因此 LangChain 一侧无需知道某个服务器使用哪个时代。

要让一个智能体同时持有来自不同时代服务器的工具，请为每个服务器分配各自的连接，使其保留服务器所支持的最佳时代，可以通过 ClientGroup 或为每个服务器使用一个适配器来实现。预构建的 fastmcp.Client 通过其 mode 参数选择时代：

python 
from fastmcp.client import Client


async def agent_across_eras(legacy_target, modern_target):
    # MCP has two protocol eras. FastMCP negotiates per connection, so a
    # separate adapter per server lets each keep the best era its own server
    # supports. `mode="legacy"` pins the handshake era; `mode="auto"` (the
    # default) negotiates the newest the server understands.
    legacy = Client(legacy_target, mode="legacy")
    modern = Client(modern_target, mode="auto")
    async with (
        MCPAdapter(legacy) as legacy_adapter,
        MCPAdapter(modern) as modern_adapter,
    ):
        tools = await legacy_adapter.list_tools() + await modern_adapter.list_tools()
        return create_agent("claude-sonnet-5", tools)

若改为将两个服务器作为单个 MCPConfig 集群传入，则会为集群中的所有内容协商出一个时代，把所有服务器降到任一成员所需的最旧时代。

完整的协商规则见 FastMCP 文档中的 协议协商。
