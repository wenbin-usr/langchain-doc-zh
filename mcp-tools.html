MCP 工具

将 MCP 工具加载到 LangChain 智能体中，控制其执行，并处理服务器返回的结果和请求。
约 8 分钟 社区翻译 查看英文原文 ↗
注意

langchain.mcp命名空间需要langchain[mcp]>=1.4.0，且处于 beta 阶段。该 API 可能发生变化。

MCPAdapter在 MCP 服务器与 LangChain 智能体之间搭建桥梁：它发现服务器所声明的工具，并将这些工具适配为标准 LangChain 工具。将list_tools()得到的工具传给create_agent，就像使用其他任何 LangChain 工具一样。

本页介绍该桥梁特有的内容：识别 MCP 工具、控制其执行、处理其输出，以及在调用期间服务器需要输入时如何响应。可运行的发现与智能体示例见MCP 快速入门。

在智能体中使用 MCP 工具#

使用MCPAdapter.list_tools发现服务器的工具目录，然后将返回的工具交给create_agent。从智能体的角度看，它们的行为与 LangChain 工具一致：模型选择工具，LangChain 调用该工具，产生的ToolMessage返回给模型。

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter


async def run_agent(server) -> dict:
    # Discover the server's tools, then hand them to the agent like any other
    # LangChain tools. The tools hold the client, so the agent stays usable
    # for the life of the adapter context.
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()
        agent = create_agent("claude-sonnet-5", tools)
        return await agent.ainvoke(
            {
                "messages": [
                    {"role": "user", "content": "What is the forecast for Oslo?"}
                ]
            }
        )

处理工具输出#

MCP 工具结果会转换为ToolMessage对象，其中包含模型可读取的内容、用于存放应用数据的 artifact，以及表示成功或失败的状态。

多模态内容#

适配器会将模型可见的 MCP 内容转换为 LangChain内容块。例如，某个工具返回带截图的 MCP 图像块时，该内容会以image块的形式到达模型。

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter
from langchain.messages import ToolMessage


async def access_multimodal_tool_content(server) -> dict:
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()
        agent = create_agent("claude-sonnet-5", tools)
        result = await agent.ainvoke(
            {"messages": [{"role": "user", "content": "Take a screenshot."}]}
        )

    # An MCP result arrives as LangChain content blocks. Image and file content
    # convert into standardized `image`/`file` blocks alongside `text`.
    for message in result["messages"]:
        if not isinstance(message, ToolMessage):
            continue
        for block in message.content_blocks:
            if block["type"] == "text":
                print(f"Text: {block['text']}")
            elif block["type"] == "image":
                preview = block.get("base64", "")[:20]
                print(f"Image mime type: {block.get('mime_type')}")
                print(f"Image base64: {preview}...")

    return result

结构化内容#

当工具返回结构化内容时，适配器会将其作为 artifact 附加到ToolMessage上，而不是将其并入模型可见的文本。运行智能体，然后从结果中的ToolMessage实例里读取artifact：

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter
from langchain.messages import ToolMessage


async def run_agent_structured(server) -> dict:
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()
        agent = create_agent("claude-sonnet-5", tools)
        result = await agent.ainvoke(
            {"messages": [{"role": "user", "content": "Look up user 42."}]}
        )

    # The adapter sets `artifact` only when the tool returned structured
    # content, so a non-None artifact always carries `structured_content`.
    for message in result["messages"]:
        if isinstance(message, ToolMessage) and message.artifact is not None:
            structured = message.artifact["structured_content"]
            print(f"Structured content: {structured}")

    return result

错误#

MCP 工具结果带有一个isError标志。当服务器报告isError=True时，适配器会将其转换为ToolMessage，其中status="error"携带服务器自身的消息，这样智能体就能读取该消息并自我纠正：

python 
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter
from langchain.messages import ToolMessage


async def divide_by_zero(server) -> dict:
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()
        agent = create_agent("claude-sonnet-5", tools)
        result = await agent.ainvoke(
            {
                "messages": [
                    {
                        "role": "user",
                        "content": "Use the divide tool to calculate 10 divided by 0.",
                    }
                ]
            }
        )

    # A server error (isError=True) reaches the model as a failed ToolMessage,
    # so the agent can read the server's own message and recover. Transport
    # failures still raise, because a model cannot act on those.
    for message in result["messages"]:
        if isinstance(message, ToolMessage) and message.status == "error":
            print(f"Tool reported: {message.text}")

    return result

服务器报告的错误会以失败的工具消息形式到达模型，而传输或会话故障则会抛出异常。

工具元数据#

每个适配后的工具都会在 LangChain 工具元数据的mcp命名空间下携带其 MCP 来源信息：

python 
tool.metadata
# {
#     "mcp": {
#         "tool": {
#             "annotations": {
#                 "destructive_hint": True,
#                 "read_only_hint": False,
#             },
#             "_meta": {"origin": "crm"},
#         },
#         "server": {
#             "name": "crm",
#             "version": "2.1.0",
#         },
#     },
# }

每个嵌套字段都是可选的：服务器可以提供工具注解、_meta、服务器标识，或其中任意组合，也可以什么都不提供。annotations包含 MCP 提示，例如read_only_hint和destructive_hint；_meta是服务器提供的不透明元数据；server标识声明该工具的 MCP 实现。

以防御性方式读取可选元数据，使缺失字段返回默认值而不是报错：

python 
from langchain.tools import BaseTool


def is_destructive(tool: BaseTool) -> bool:
    """Read the MCP destructive hint off the adapter's tool metadata."""
    # Chain `.get` with defaults so a tool missing any nested field returns
    # False rather than raising.
    annotations = (
        (tool.metadata or {}).get("mcp", {}).get("tool", {}).get("annotations", {})
    )
    return annotations.get("destructive_hint", False)

人在回路#

读取注解使你能够依据服务器对工具的声明来拦截工具调用，而无需硬编码工具名称。MCP 注解对工具进行分类，LangChain 的人在回路中间件负责执行审批策略。

在工具发现阶段从元数据中读取一次 destructive 提示。然后为人在回路配置提供一个when谓词，它接收每个待处理的工具调用，并返回该调用是否需要审批：

python 
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain.agents.middleware.human_in_the_loop import InterruptOnConfig
from langchain.tools import BaseTool
from langchain.tools.tool_node import ToolCallRequest


def is_destructive(tool: BaseTool) -> bool:
    """Read the MCP destructive hint off the adapter's tool metadata."""
    annotations = (
        (tool.metadata or {}).get("mcp", {}).get("tool", {}).get("annotations", {})
    )
    return annotations.get("destructive_hint", False)


async def gate_destructive_tools(server):
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()

        # Read the destructive hint from metadata once, then let a callable
        # decide per call. One config covers whatever destructive tools a
        # server exposes, without hardcoding tool names.
        destructive = {tool.name for tool in tools if is_destructive(tool)}

        def needs_approval(request: ToolCallRequest) -> bool:
            return request.tool_call["name"] in destructive

        gate = InterruptOnConfig(
            allowed_decisions=["approve", "reject"], when=needs_approval
        )
        interrupt_on: dict[str, bool | InterruptOnConfig] = {
            tool.name: gate for tool in tools
        }
        return create_agent(
            "claude-sonnet-5",
            tools,
            middleware=[HumanInTheLoopMiddleware(interrupt_on=interrupt_on)],
            checkpointer=InMemorySaver(),
        )

当智能体调用被该谓词拦截的工具时，运行会暂停。批准该调用即可执行，拒绝则跳过该工具并告知模型：

python 
from langgraph.types import Command

# Approve the pending destructive call and resume.
resumed = await agent.ainvoke(
    Command(resume={"decisions": [{"type": "approve"}]}), config
)

该谓词还可以检查调用的参数。这样，工具能在输入安全时自由运行，仅在输入有风险时暂停，例如针对受保护路径的delete_file调用。

通过request.tool_call["args"]访问这些参数。

结合元数据分类和参数检查，只在工具类型和输入需要审批时才拦截该工具。完整的审批工作流程请参阅人在回路。

工具执行期间的服务器请求#

大多数工具在调用过程中无需向客户端索取任何信息即可完成。当服务器需要输入时，MCPAdapter会将elicitation呈现为 LangGraphinterrupt。

Elicitation#

Elicitation允许 MCP 服务器在工具调用期间请求输入。适配器会通过 LangGraph 中断暂停运行。你的应用将请求呈现给用户，并用用户的回答恢复运行。通过其 MCP 端点暴露的智能体暂停时，Agent Server 会以这种方式请求输入。更多信息请参阅基于 MCP 的人在回路。

为智能体附加检查点保存器，并在调用和恢复它时使用同一个thread_id。

本示例假设预订工具只询问一个日期并暂停一次。请将该示例日期替换为用户的实际回答。

python 
from typing import Any

from langchain.agents import create_agent
from langchain.mcp import MCPAdapter
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command


async def book_with_elicitation(server) -> dict:
    # Elicitation is handled automatically: when a server needs input mid-call,
    # the adapter surfaces the question as a LangGraph `interrupt()`, so the
    # person already reviewing the agent's work answers it and the run resumes.
    async with MCPAdapter(server) as adapter:
        tools = await adapter.list_tools()

        # Resuming a paused run needs persistence, so the interrupted run has
        # somewhere to wait.
        agent = create_agent("claude-sonnet-5", tools, checkpointer=InMemorySaver())
        config: Any = {"configurable": {"thread_id": "booking-1"}}

        paused = await agent.ainvoke(
            {"messages": [{"role": "user", "content": "Book a table for 4."}]}, config
        )
        [interrupt] = paused["__interrupt__"]
        [question] = interrupt.value["requests"]

        # Answers are keyed by the server's own request key, so nothing has to
        # be tracked across the pause. `decline` or `cancel` would refuse.
        answer = {"action": "accept", "content": {"date": "2026-09-14"}}
        return await agent.ainvoke(
            Command(resume={"responses": {question["key"]: answer}}), config
        )

Elicitation 默认开启。适配器会声明该能力并驱动中断循环。若预构建客户端本身已带有 elicitation 处理器，则尊重该处理器而不覆盖它。

使用Command(resume={"responses": {key: answer}})恢复运行。中断负载和回答类型位于langchain.mcp.elicitation中。

注意

恢复运行会从头重新执行该工具。在服务器请求输入之前完成的任何工作都可能重复执行。请确保该工作可安全重复，且不会产生重复的副作用。

每个回答使用以下动作之一：

  • accept：提供与请求 schema 匹配的表单content，或在没有content的情况下确认 URL 交互已完成。

  • decline：拒绝提供所请求的信息。

  • cancel：表示用户取消了该交互。

适配器会将回答转发给服务器，由服务器决定工具调用如何结束。

只有 elicitation 会以这种方式得到回答。如果服务器请求的是sampling或roots，则会抛出错误，因为现代的无会话协议没有为这些请求提供实时反向通道。请参阅Sampling 与 roots。

注意

由中断驱动的 elicitation 用于回答以InputRequiredResult形式返回请求的服务器。仅通过旧版握手会话推送 elicitation 的服务器无法以这种方式回答。
