LangChain/开始使用/设计理念

设计理念

LangChain 的存在，是为了成为使用 LLM 构建应用最容易上手的起点，同时保持灵活并可用于生产。
约 6 分钟 社区翻译 查看英文原文 ↗

LangChain 由几个核心理念驱动：

  • 大语言模型（LLM）是出色而强大的新技术。

  • 当 LLM 与外部数据源结合时，效果会更好。

  • LLM 将改变未来应用的面貌。具体而言，未来的应用会越来越具有智能体特征。

  • 这场变革仍处于非常早期的阶段。

  • 尽管构建这类智能体应用的原型很容易，但要构建足够可靠、能够投入生产的智能体仍然非常困难。

如今，开发者可以自行选择构建智能体的方式：使用 LangChain 获得最大的灵活性与控制力，或使用 Deep Agents——它提供类似的灵活性与控制力，同时内置了有明确主张的规划、文件系统工具、子智能体和上下文管理。两者都构建在 LangGraph 之上。

借助 LangChain，我们有两个核心关注点：

1. 我们希望让开发者能够使用最好的模型进行构建。

不同提供商提供不同的 API，模型参数和消息格式也各不相同。标准化这些模型输入与输出是我们的核心关注点，它让开发者能够轻松切换到最新的最先进模型，避免被锁定。

2. 我们希望让开发者能轻松使用模型来编排与其他数据和计算交互的更复杂流程。

模型不应只用于 文本生成——它们还应用于编排与其他数据交互的更复杂流程。LangChain 让定义 LLM 可动态使用的 工具变得简单，并有助于解析和访问非结构化数据。

历史#

鉴于该领域不断变化的节奏，LangChain 也随时间演进。以下是 LangChain 多年来变化的简要时间线，它与“用 LLM 构建应用”这一含义的演变相伴而行：

2022-10-24

v0.0.1

在 ChatGPT 发布的一个月前，LangChain 作为一个 Python 包发布。它由两个主要部分组成：

  • LLM 抽象

  • “链”（Chains），即为常见用例预先确定的计算步骤。例如 RAG：先运行检索步骤，再运行生成步骤。

LangChain 这个名字来自“Language”（如语言模型）和“Chains”（链）。

2022-12

首批通用智能体被加入 LangChain。

这些通用智能体基于 ReAct 论文（ReAct 代表 Reasoning and Acting，即推理与行动）。它们使用 LLM 生成表示工具调用的 JSON，然后解析该 JSON 以确定要调用哪些工具。

2023-01

OpenAI 发布“Chat Completion”API。

此前，模型接收字符串并返回字符串。在 ChatCompletions API 中，它们演变为接收消息列表并返回一条消息。其他模型提供商也纷纷跟进，LangChain 随之更新以支持消息列表。

2023-01

LangChain 发布 JavaScript 版本。

LLM 和智能体将改变应用的构建方式，而 JavaScript 是应用开发者使用的语言。

2023-02

LangChain Inc. 作为一家公司成立，围绕开源项目 LangChain 展开。

主要目标是“让智能体无处不在”。团队认识到，尽管 LangChain 是关键一环（它让上手 LLM 变得简单），但还需要其他组件。

2023-03

OpenAI 在其 API 中发布“函数调用”。

这使得 API 能够显式生成表示工具调用的载荷。其他模型提供商纷纷跟进，LangChain 也更新为将此作为工具调用的首选方式（而非解析 JSON）。

2023-06

LangSmith 发布，是 LangChain Inc. 的闭源平台，提供可观测性和评估。

构建智能体的主要问题是让它们可靠，而提供可观测性和评估的 LangSmith 正是为解决这一需求而生。LangChain 也更新为与 LangSmith 无缝集成。

2024-01

v0.1.0

LangChain 发布 0.1.0，这是首个非 0.0.x 版本。

行业从原型走向生产，因此 LangChain 更加关注稳定性。

2024-02

LangGraph 发布，作为一个开源库。

最初的 LangChain 有两个关注点：LLM 抽象，以及用于上手常见应用的高层接口；然而，它缺少一个低层编排层，让开发者能够控制智能体的确切流程。于是有了 LangGraph。

在构建 LangGraph 的过程中，我们吸取了构建 LangChain 的经验教训，并加入了我们发现确实需要的功能：流式传输、持久化执行、短期记忆、人在回路等。

2024-06

LangChain 拥有 700 多个集成。

集成被拆分出 LangChain 核心包，要么移入各自独立的包（针对核心集成），要么 langchain-community。

2024-10

LangGraph 成为构建任何不止一次 LLM 调用的 AI 应用的首选方式。

随着开发者试图提升应用的可靠性，他们需要比高层接口所提供的更多控制力。LangGraph 提供了这种低层灵活性。LangChain 中的大多数链和智能体被标记为弃用，并附有如何将它们迁移到 LangGraph 的指南。LangGraph 中仍保留一个高层抽象：智能体抽象。它构建在低层 LangGraph 之上，接口与 LangChain 的 ReAct 智能体相同。

2025-04

模型 API 变得更加多模态。

模型开始接受文件、图像、视频等。我们相应更新了 langchain-core 消息格式，让开发者能以标准方式指定这些多模态输入。

2025-10-20

v1.0.0

LangChain 发布 1.0，带来两项重大变化：

  1. 对 langchain 中所有链和智能体进行了彻底重构。所有链和智能体现在都被替换为唯一的高层抽象：构建在 LangGraph 之上的智能体抽象。这个高层抽象最初在 LangGraph 中创建，现在只是移到了 LangChain。

    对于仍在使用旧版 LangChain 链/智能体且不想升级的用户（注意：我们建议你升级），你可以通过安装 langchain-classic 包继续使用旧版 LangChain。

  2. 标准消息内容格式：模型 API 从返回带有简单内容字符串的消息，演变为更复杂的输出类型——推理块、引用、服务端工具调用等。LangChain 演进其消息格式，以便在各提供商之间实现标准化。

2026-03-15

v0.5.3

Deep Agents 发布，作为一个构建在 LangGraph 之上的开源智能体运行框架。

虽然 LangChain 为自定义智能体架构提供了灵活的构建块，但 Deep Agents 为研究和编码等复杂、长时间运行的任务提供了开箱即用的方案。它内置了规划工具、带可插拔后端（内存、磁盘、LangGraph store、沙箱）的虚拟文件系统，以及用于隔离上下文的子智能体派生能力。若需要具备预定义工具、更自主的智能体，请使用 Deep Agents；若需要完全掌控智能体架构，请使用 LangChain。
