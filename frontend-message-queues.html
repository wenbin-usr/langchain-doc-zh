消息队列

在智能体顺序处理时排队多条消息并对其进行管理
约 7 分钟 社区翻译 查看英文原文 ↗

消息排队让用户可以在不等待智能体处理完当前消息的情况下快速连续发送多条消息。每条消息都会被立即接受、排入活动线程的队列，并按顺序处理，让你对等待中的工作拥有完整的可见性和控制权。

注意

此功能需要 LangGraph Agent Server。你可以使用 langgraph dev 在本地运行智能体，或 将其部署到 LangSmith 来使用此模式。

为什么需要消息队列？#

在典型的聊天界面中，用户必须等待智能体完成回复后才能发送下一条消息。这在多种场景下会造成不便：

  • 批量提问：用户希望一次性提出五个相关问题，而不是等待每个答案

  • 追问链：在智能体仍在工作时提交澄清或补充上下文

  • 自动化测试序列：以编程方式发送一系列提示词以验证智能体行为

  • 数据录入工作流：依次输入结构化数据以进行处理

消息队列通过立即接受所有提交并按顺序处理来解决这一问题。

这是智能体 UX 的一项基础能力，而非表面的聊天功能。SDK 将队列作为流控制器的一部分进行跟踪，因此你的 UI 可以显示待处理的工作、取消过期请求，并在当前运行继续时保持输入框可用。

工作原理#

当你希望某个提交排在正在运行的请求之后时，传入 multitaskStrategy: "enqueue"。在智能体处理期间，排队的提交会被添加到活动线程的队列中。当前运行完成后，下一条排队消息会被自动发送。

使用与你所用框架配套的队列辅助工具读取队列状态：

属性类型说明
queue.entriesSubmissionQueueEntry[]所有待处理队列条目组成的数组
queue.sizenumber当前队列中的条目数量
queue.cancel(id)(id: string) => Promise<void>按 ID 取消指定的队列条目
queue.clear()() => Promise<void>取消所有队列条目

每个 SubmissionQueueEntry 对象包含：

字段类型说明
idstring此队列条目的唯一标识符
valuesobject已提交的输入值（包括消息）
optionsobject随提交传递的任何附加选项
createdAtstring该条目创建时间的 ISO 时间戳

设置 useStream#

将 useStream 连接到你的智能体，然后搭配与你所用框架配套的提交队列辅助工具。在运行进行中时调用 stream.submit() 发送消息；对于需要排在活动请求之后等待的提交，传入 multitaskStrategy: "enqueue"。读取 queue.entries 和 queue.size 以渲染待处理的工作，并使用 queue.cancel() 或 queue.clear() 在条目开始处理之前将其移除。

注意

这些代码示例使用 useStream<typeof myAgent> 来实现类型安全的流状态。关于 Python 或 JavaScript 后端的类型推断，请参阅类型推断。

React 
import { useStream, useSubmissionQueue } from "@langchain/react";

function Chat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "simple_agent",
  });
  const queue = useSubmissionQueue(stream);

  const handleSubmit = (text: string) => {
    stream.submit({
      messages: [{ type: "human", content: text }],
    });
  };

  const pendingCount = queue.size;
  const entries = queue.entries;

  return (
    <div>
      <MessageList messages={stream.messages} />
      {pendingCount > 0 && <QueueList entries={entries} queue={queue} />}
      <ChatInput onSubmit={handleSubmit} />
    </div>
  );
}
Vue

Angular

import { injectStream, injectSubmissionQueue } from "@langchain/angular";

@Component({

    <message-list [messages]="stream.messages()" />

      <queue-list [entries]="queue.entries()" [queue]="queue" />
    }
    <chat-input (onSubmit)="handleSubmit($event)" />
  `,
})
export class ChatComponent {
  stream = injectStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "simple_agent",
  });
  queue = injectSubmissionQueue(this.stream);

  handleSubmit(text: string) {
    this.stream.submit({
      messages: [{ type: "human", content: text }],
    });
  }
}

显示队列#

构建一个 QueueList 组件，用于显示每条待处理消息及其取消按钮。这让用户能够了解正在等待的内容，并移除不再需要的条目。

tsx 
function QueueList({ entries, queue }) {
  return (
    <div className="queue-panel">
      <div className="queue-header">
        <span>Queued messages ({entries.length})</span>
        <button onClick={() => queue.clear()}>Clear all</button>
      </div>
      <ul className="queue-entries">
        {entries.map((entry) => {
          const text = entry.values?.messages?.at(-1)?.content ?? "Pending...";
          return (
            <li key={entry.id} className="queue-entry">
              <span className="queue-text">{text}</span>
              <span className="queue-time">
                {new Date(entry.createdAt).toLocaleTimeString()}
              </span>
              <button
                className="queue-cancel"
                onClick={() => queue.cancel(entry.id)}
              >
                Cancel
              </button>
            </li>
          );
        })}
      </ul>
    </div>
  );
}
提示

将每条排队消息的前几个字符作为预览显示，以便用户无需阅读完整消息就能快速判断要取消哪些条目。

取消排队消息#

取消操作有两个层级：

取消单条条目#

按 ID 从队列中移除指定的消息。智能体将跳过它并处理下一条条目。

typescript 
await queue.cancel(entryId);

清空整个队列#

一次性移除所有待处理消息。适用于用户切换上下文或想要重新开始的场景。

typescript 
await queue.clear();
注意

取消队列条目仅对 尚未开始处理 的消息生效。如果智能体已经在处理某条消息，将其从队列中取消不会有任何效果。请使用 stream.stop() 中断当前运行。

使用 onCreated 串联后续提交#

onCreated 回调会在创建新运行时触发，为你提供一个以编程方式提交后续消息的钩子。这适用于构建多步工作流，即下一个问题取决于前一个提交是否被接受。

typescript 
stream.submit(
  { messages: [{ type: "human", content: "What is quantum computing?" }] },
  {
    onCreated(run) {
      console.log("Run created:", run.runId);
      // Chain a follow-up
      stream.submit({
        messages: [{ type: "human", content: "Give me a simple analogy." }],
      });
    },
  }
);

这种模式会自然地填充队列。第一条消息立即开始处理，后续消息则排在其后。

启动新线程#

当用户想要开始全新对话时，更新传入流的响应式 threadId。传入 null 会清除当前线程绑定；下一次提交将创建新线程。

React 
function NewThreadButton() {
  const [threadId, setThreadId] = useState<string | null>(null);
  const stream = useStream<typeof myAgent>({ threadId, onThreadId: setThreadId });

  return (
    <button onClick={() => setThreadId(null)}>
      New conversation
    </button>
  );
}
Vue 
<script setup lang="ts">
const threadId = ref<string | null>(null);
const stream = useStream<typeof myAgent>({
  threadId,
  onThreadId: (id) => (threadId.value = id),
});
</script>

<template>
  <button @click="threadId = null">New conversation</button>
</template>
Svelte 
<script lang="ts">
  let threadId = $state<string | null>(null);
  const stream = useStream<typeof myAgent>({
    threadId: () => threadId,
    onThreadId: (id) => (threadId = id),
  });
</script>

<button onclick={() => (threadId = null)}>New conversation</button>
Angular 
threadId = signal<string | null>(null);
stream = injectStream<typeof myAgent>({
  threadId: this.threadId,
  onThreadId: (id) => this.threadId.set(id),
});

最佳实践#

  • 限制队列长度：虽然客户端没有硬性的队列长度限制，但请注意过大的队列会降低用户体验。考虑在队列超过合理阈值（例如 10 条）时显示警告。

  • 显示队列位置：为每个排队条目编号，让用户了解处理顺序。

  • 保持输入焦点：提交后保持输入框聚焦，以便用户立即输入下一条消息。

  • 为过渡添加动画：条目开始处理时，将其从队列面板平滑移动到消息列表。

  • 妥善处理错误：如果某条排队消息失败，应呈现错误，同时不阻塞后续队列条目。

  • 对快速提交做防抖：对于自动化或程序化提交，在消息之间加入短暂延迟，避免给服务器造成过大压力。
