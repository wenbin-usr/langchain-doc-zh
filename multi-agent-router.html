路由器

在 路由器架构中，路由步骤会对输入进行分类，并将其分发到专门的智能体。当你拥有彼此独立的垂直领域（各自需要专属智能体的独立知识域）时，这种架构很有用。

关键特性#

  • 路由器会拆解查询

  • 并行调用零个或多个专门智能体

  • 将结果综合为连贯的回复

何时使用#

当你拥有彼此独立的垂直领域（各自需要专属智能体的独立知识域）、需要并行查询多个来源，并希望将结果综合为统一的回复时，可以使用路由器模式。

基础实现#

路由器会对查询进行分类，并将其分发到合适的智能体。单智能体路由使用 Command，并行分发到多个智能体则使用 Send。

使用 Command 路由到单个专门智能体：

python 
from langgraph.types import Command

def classify_query(query: str) -> str:
    """Use LLM to classify query and determine the appropriate agent."""
    # Classification logic here
    ...

def route_query(state: State) -> Command:
    """Route to the appropriate agent based on query classification."""
    active_agent = classify_query(state["query"])

    # Route to the selected agent
    return Command(goto=active_agent)

使用 Send 并行分发到多个专门智能体：

python 
from typing import TypedDict
from langgraph.types import Send

class ClassificationResult(TypedDict):
    query: str
    agent: str

def classify_query(query: str) -> list[ClassificationResult]:
    """Use LLM to classify query and determine which agents to invoke."""
    # Classification logic here
    ...

def route_query(state: State):
    """Route to relevant agents based on query classification."""
    classifications = classify_query(state["query"])

    # Fan out to selected agents in parallel
    return [
        Send(c["agent"], {"query": c["query"]})
        for c in classifications
    ]

无状态与有状态#

两种方式：

  • 无状态路由器 独立处理每个请求

  • 有状态路由器 在请求之间保留对话历史

无状态#

每个请求都独立路由——调用之间没有记忆。多轮对话请参见 有状态路由器。

提示

路由器与子智能体：两种模式都能将工作分发给多个智能体，但它们在路由决策的产生方式上有所不同：

  • 路由器：一个专门的路由步骤（通常是一次 LLM 调用或基于规则的逻辑），负责对输入进行分类并分发到各个智能体。路由器本身通常不维护对话历史，也不执行多轮编排——它只是一个预处理步骤。

  • 子智能体：由主监督智能体在持续进行的对话中动态决定调用哪些 子智能体。主智能体维护上下文，可以跨轮次调用多个子智能体，并编排复杂的多步骤工作流。

当你有清晰的输入类别，并希望采用确定性或轻量级的分类时，使用 路由器。当你需要灵活、能感知对话的编排，由 LLM 根据不断演化的上下文决定下一步做什么时，使用 监督者。

有状态#

对于多轮对话，你需要在多次调用之间维护上下文。

工具包装#

最简单的方式：将无状态路由器包装成一个工具，供对话式智能体调用。对话式智能体负责记忆与上下文，路由器则保持无状态。这样避免了在多个并行智能体之间管理对话历史的复杂性。

python 
@tool
def search_docs(query: str) -> str:
    """Search across multiple documentation sources."""
    result = workflow.invoke({"query": query})
    return result["final_answer"]

# Conversational agent uses the router as a tool
conversational_agent = create_agent(
    model,
    tools=[search_docs],
    prompt="You are a helpful assistant. Use search_docs to answer questions."
)

完整持久化#

如果你需要路由器本身维护状态，可以使用 持久化 来存储消息历史。在路由到某个智能体时，从状态中获取之前的消息，并有选择地将它们纳入该智能体的上下文——这是 上下文工程 的一个抓手。

警告

有状态路由器需要自定义历史管理。 如果路由器在不同轮次之间切换智能体，当各智能体的语气或提示词不同时，终端用户可能会觉得对话不够流畅。采用并行调用时，你需要在路由器层面维护历史（输入与综合输出），并在路由逻辑中利用这些历史。可以考虑改用 交接模式 或 子智能体模式——两者都为多轮对话提供了更清晰的语义。
